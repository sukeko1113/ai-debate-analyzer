## 1. 立論の役割とHEnDAの制約（v01から継承）

| 項目 | 組み立て時の判断 |
| --- | --- |
| 肯定立論 | 論題の肯定を支持するプランとADを示す。ADは最大2つ |
| 否定立論 | 肯定側の政策から生じるDAを示す。DAは最大2つ。相手のADが証明不足だという攻撃だけで立論を置き換えない |
| プラン | 肯定立論の冒頭で明確に提示。事前の論題定義の範囲内とし、立論後は変更・追加しない |
| ADの三要素 | 政策なしの問題、政策による改善の仕組み、その改善の重要性 |
| DAの三要素 | 政策なしで保たれる状態、政策による悪化の仕組み、その悪化の重要性 |
| 時間・語数 | 立論は各4分。平均150語／分程度を超えず、最大600語。上限まで詰めることを目標にしない |
| 反転 | 新AD／DAに相当するCase flip・Link turnは基本的に立論で扱う。価値だけのValue turnとは区別 |

根拠：資料1 §§2.1.1〜2.1.4、2.1.10。

### 1.1 「二つ」の意味と、二重計上の予防（v02で強化）

一つのADに独立した三つの利益を束ねても、一つと扱われるとは限らない。逆に、**見出しを二つに分けても、同じ人の同じ利益なら実質は一つ**である。

総括で相手からW04（二重計上）を受けると、AD1とAD2の合計が主張どおりに立たない。立論の段階で次の三つを確認する。

1. **受益者が違うか**（同じ生徒か、別の集団か）
2. **改善する内容が違うか**（同じ「参加機会」を言い換えていないか）
3. **片方が崩れたとき、もう片方が独立に残るか**

3つ目が最も確実な判定法である。AD1のBリンクが切れたときAD2も同時に崩れるなら、それは独立した二つではない。

> **アプリ連携**：この判定結果を `issue_snapshots.overlap_with_issue_id` / `overlap_ratio` に記録する。AIは重複候補までを出し、独立性の確定は人が行う。

### 1.2 否定側の立論とAttackの分業

「政策から利益が出ない」「必要ない」は基本的に否定Attackの役割（攻撃資料 P・C・S系）。「実施費用が不足するので解決性が低い」はAttack（S03）になり得るが、「支出により別の教育支援を失う」は独立DAとして立論で証明する（L09）。

**規則の根拠（v03で追加）**　R1 §2.1.2.2 は、否定立論では論題・プランから生じるDisadvantageの証明に時間を使うこととし、**立論での時間が余ってしまった場合などにのみ**、肯定側Advantageの証明の不備を攻撃するアタックが許されるとしている。側注はさらに、「プランからAdvantageが生じない」「プランは必要ない」という種類の議論は否定アタックの担当者が行うべき事柄であり、立論以外ではDisadvantageを論じることはできない、としている。

また同じ側注は、「プラン実行に莫大なコストがかかる」という主張は実際にはDisadvantageであってアタックとしては禁止される一方、「コストをまかないきれない関係で解決性が落ちる」はアタックとして許される、と線を引いている。**L09（資源圧迫型DA）とS03（能力・予算・人員不足）の境界はここにある。**

## 2. 政策と比較世界を固定する（v01から継承）

### 2.1 プランの六つの確認点

| 確認点 | 書く内容 |
| --- | --- |
| 誰が | 政策を実施する主体。論題定義に従う |
| 誰に | 対象地域・年齢・機関等。都合よく一部へ狭めない |
| 何を | 義務化・支援・禁止・導入等の具体的措置 |
| いつ | 開始・継続の条件。大会で定める仮定を勝手に変えない |
| どのように | 効果に不可欠な実施条件を明示。後から補完策を生やさない |
| 何と比べるか | 政策なしの見通しと政策ありの見通しを、同じ対象・期間で比べる |

**「どのように」を書かないと何が起きるか**：S02（不可欠な前提が欠ける）を受けたとき、Defenseで補完策を足すしかなくなる。それはR02（後出しのプラン変更）として判定材料から外れる。**立論で書いておくことだけが唯一の防御**である。

### 2.2 政策なし＝何も変わらない世界、ではない

現行制度の継続、既定の変更、合理的に見込まれる行動変化も比較対象になる。「今ある問題の総量」をそのまま政策の利益にしない。DAも、もともとある被害ではなく政策が増やす分を説明する（P05・P06・P08の予防）。

### 2.3 唯一性と必要性を混同しない

他の方法が存在してもこの政策の追加利益が証明されればADは成立し得る。逆に、新しい方法であるだけでは価値は証明されない（P03〜P08・A01〜A08の予防）。

## 3. 立論を作る九つの手順（v02で工程9を追加）

| 工程 | 内容 |
| --- | --- |
| 1 | **一文の結論**：「政策により、誰の何がどう変わるか」。分野名ではなく変化を書く |
| 2 | **比較前の状態**：政策がない場合、その問題・望ましい状態がなぜ続くか |
| 3 | **因果を分解**：政策→行動・制度の変化→中間結果→最終利益／被害。矢印ごとに理由を言えるか |
| 4 | **根拠を配置**：現状の統計、行動変化の研究、最終的な影響の説明をそれぞれ置く。一つの証拠に全役割を負わせない |
| 5 | **価値を説明**：§5の8次元のどれで重要なのかを特定する（v02で強化） |
| 6 | **成立範囲を限定**：誰に、どの条件で、どの程度成立するか。「必ず」「全員」を不要に使わない |
| 7 | **攻撃に耐えるか確認**：予想攻撃IDで自己攻撃し、プラン変更なしで答えられるか点検 |
| 8 | **聞いて理解できる原稿へ**：見出しを短く、証拠の後に理由と結論への意味。音読して削る |
| **9** | **独立性を確認**（v02で追加）：§1.1の三つの確認。二本目が一本目に依存するなら一本に統合する |

## 4. 各型の標準ノード構成（v02で新設）

アプリのA/B/C抽出と完全性検査の基準になる。**この構成は「最低限これが要る」という意味であって、点数の配分ではない。**

| ノード | 意味 | 立論での書き方 |
| --- | --- | --- |
| **A（Observation）** | 現状・前提。ADなら「現状に問題がある」、DAなら「現状では悪影響が起きていない」 | 工程2 |
| **B1..Bn（Link）** | 政策から結果へつながる因果。Effect / Solvency / Process | 工程3。矢印1本＝Bノード1つ |
| **C（Impact）** | 結果がどれほど重要・重大か | 工程5 |
| **Support Quality** | Evidence / Warrant / Relevance / Burden。A・B・Cが成立すると評価される理由 | 工程4 |

**Bの段数の目安**：2〜4段。1段は飛躍を疑われ（C07）、5段以上は各段の証明が薄くなる（C07・C02）。L08（長期波及型）だけは例外的に多段になるので、段ごとの脱落条件を明示する。

> **アプリ連携**：`argument_nodes.node_type ∈ {A_OBSERVATION, B_LINK, C_IMPACT, OTHER}`、`link_order` はB_LINKのみが持つ。型ごとの標準段数を下回る／上回る場合、`rule_flags` に完全性の候補フラグを立てる（自動除外はしない）。

## 5. Impactを8次元で書き分ける（v02で新設・最重要）

v01は工程5を「人数・深刻さ・期間・公平性等のうち、重要な理由を示す」としていた。これでは足りない。攻撃側のI01〜I08は**8つの別々の次元**を狙ってくるので、どの次元で重要と主張しているかを立論で特定しておかないと、防御のときに論点がずれる。

| 次元 | 主張の形 | 狙われる攻撃 | 立論で書くべきこと |
| --- | --- | --- | --- |
| **scale｜規模** | 何人・どの範囲に及ぶか | I01 | 対象の定義と人数の根拠。「全員」と書かない |
| **occurrence_likelihood｜発生可能性** | その結果が実際に起きる見込み | I02 | 条件が揃う根拠。Bリンクの確からしさとは別に、C自体の発生条件 |
| **severity｜深刻さ** | 一人に何がどの程度起きるか | I03 | 具体的な変化。「大きい」で終えない |
| **timeframe｜時期・期間** | いつ始まり、どれだけ続くか | I04・S07 | 発現時期と持続条件 |
| **reversibility｜可逆性** | 元へ戻せるか、回復負担は何か | I05 | 戻せない理由。単なる変更費用と区別 |
| **equity｜公平性・分配** | 誰が得て誰が負担するか | I06 | 層別の効果。平均で代表させない |
| **value_relevance｜指標と価値の一致** | 測った結果が、主張する価値を意味するか | I07・M04 | 指標と価値をつなぐ理由 |
| **marginal_utility｜限界効果** | 追加一単位にどれだけの価値があるか | I08・P08 | 既存の充足水準と、追加分の価値 |

**使い方**：一つのADにつき**主次元を1つ、副次元を最大2つ**。全部を主張すると、どれも薄くなり、かつ総括での比較軸が定まらない。

**教材上の意味**：初心者の立論が「重要です」で終わるのは、次元を選んでいないからである。この表から1つ選ばせるだけで、工程5の質が変わる。

> **アプリ連携**：`argument_nodes`（C_IMPACT）に `impact_dimension_primary` と `impact_dimension_secondary[]` を持たせる。攻撃側の `clash_events.impact_dimension` と突き合わせて、「主張した次元と攻撃された次元が一致しているか」を判定できる。一致していなければ、その攻撃はR05（藁人形・対象違い）の候補になる。

## 6. Starter 3｜最初に覚える3つの型（v03で新設）

L01〜L16と8次元を一度に見せると初心者には重い。**最初はこの3つだけでよい。**

| 型 | 立場 | 一文でいうと | 主次元 |
| --- | --- | --- | --- |
| **L01 問題解消型AD** | 肯定 | 今ある問題を、政策が減らす | severity |
| **L02 機会・アクセス拡大型AD** | 肯定 | できなかった人が、できるようになる | scale |
| **L09 資源圧迫・機会費用型DA** | 否定 | 政策に資源を使うと、今やっていることが減る | severity |

この3つを選んだ理由は、**肯定2・否定1で試合が成立し、かつ互いに正面からぶつかる**からである。L01/L02で「誰かが救われる」と言い、L09で「別の誰かが失う」と言う。この対立が総括の比較（G06 規模・深刻さ重視型）にそのまま乗る。

### 6.1 Starter 3 の書き方（穴埋め）

**L01｜問題解消型AD**

> A（現状）　今、［誰］は［どんな問題］に直面しています。［出典］によると［数値・事実］。
> B1（政策の作用）　プランは［問題の原因］に対して［措置］を行います。
> B2（結果）　その結果、［誰］の［問題］が［どれだけ］減ります。
> C（重要性）　これは［誰］にとって［どれだけ深刻な］ことが減るという意味で重要です。

**L02｜機会・アクセス拡大型AD**

> A（現状）　今、［誰］は［障壁］があるため［活動］に参加できていません。
> B1（障壁の除去）　プランは［障壁］を取り除きます。
> B2（参加）　その結果、［何人］が新たに参加できるようになります。
> C（重要性）　参加できなかった［誰］が参加できるという意味で重要です。

**L09｜資源圧迫・機会費用型DA**

> A（現状）　今、［限られた資源］は［既存の活動］に使われています。
> B1（資源の移動）　プランを実施すると、［その資源］が［新しい業務］へ移ります。
> B2（既存活動の縮小）　その結果、［既存の活動］が［どれだけ］減ります。
> C（重要性）　［既存の活動］を必要としている［誰］が失うという意味で重要です。

### 6.2 Starter 3 でよくある3つの失敗

| 失敗 | 直し方 |
| --- | --- |
| B1とB2をまとめて1文にする | 矢印は必ず分ける。「配ったら学力が上がる」は2段抜けている |
| Cが「大切です」で終わる | §5の8次元から1つ選び、その言葉を使う |
| L09で「お金がかかる」で止まる | **何を失うか**を書く。金額だけではDAにならない（攻撃資料 S03との境界） |

### 6.3 次に進む順

Starter 3 が書けたら、L03（予防型）とL10（行動の逆効果型）へ進む。この2つは主次元が `occurrence_likelihood` で、「本当に起きるのか」を証明する練習になる。§12.1の第2段階がそこに当たる。

## 7. 立論の構築パターン L01〜L16

各カードの読み方：

```
組み立て　標準的なA→B→Cの並び
例・使い方　仮想例
ジャッジの確認　成立を見るポイント
メタ　主Impact次元｜標準B段数｜予想攻撃ID｜難易度｜頻出度
```

難易度：★＝初心者向け／★★＝中級／★★★＝上級。頻出度：高・中・低。

### AD（肯定側の利点）

#### L01　問題解消型AD
**組み立て**　既存の問題→原因に作用する政策→問題軽減→重要性。
**例・使い方**　情報が届かない人への案内により、参加の機会を広げる。
**ジャッジの確認**　問題の実在、政策と原因の接続、軽減分。
**メタ**　主次元 severity｜B 2〜3段｜予想攻撃 P01・P07・C01・S01｜★｜高

#### L02　機会・アクセス拡大型AD
**組み立て**　利用を妨げる障壁→障壁の除去→参加→参加の価値。
**例・使い方**　距離が障壁ならオンライン提供で接点を増やす。
**ジャッジの確認**　アクセス増加と学力向上を同一視しない。利用の条件も証明。
**メタ**　主次元 scale｜B 2〜3段｜予想攻撃 S02・S04・E08・I07｜★｜高

#### L03　予防・リスク低減型AD
**組み立て**　政策なしで起き得る被害→予防の機序→減るリスク→回避の価値。
**例・使い方**　見落としを防ぐ確認手順を設ける。
**ジャッジの確認**　被害の大きさだけでなく、発生経路と減少の根拠。
**メタ**　主次元 probability｜B 2〜3段｜予想攻撃 I02・P05・C05｜★★｜中

#### L04　効率・負担軽減型AD
**組み立て**　現状の無駄→工程の変化→時間等の削減→その意味。
**例・使い方**　重複入力を減らし、指導に使う時間を増やす。
**ジャッジの確認**　削減した時間が実際に別の活動へ使えるか。移行負担との期間整合。
**メタ**　主次元 marginal_utility｜B 3段｜予想攻撃 S08・I08・I04｜★★｜中

#### L05　質・能力向上型AD
**組み立て**　現在の質的不足→練習や支援の変化→能力向上→価値。
**例・使い方**　具体的なフィードバックで論拠の組み立てを改善する。
**ジャッジの確認**　満足度・利用量・能力を分ける。
**メタ**　主次元 value_relevance｜B 3段｜予想攻撃 M04・I07・E08・C02｜★★｜高

#### L06　公平性・格差縮小型AD
**組み立て**　層別の不均衡→不利な層への作用→格差の縮小→公平性。
**例・使い方**　支援の少ない学校へ教材を届ける。
**ジャッジの確認**　平均改善だけで格差縮小を結論づけない。取り残される層も確認。
**メタ**　主次元 equity｜B 2〜3段｜予想攻撃 I06・M02・P08｜★★｜中

#### L07　選択・自律性向上型AD
**組み立て**　選択の制約→選択可能性の拡大→自律性の利益。
**例・使い方**　選べる学習手段を増やし、事情に合う参加を可能にする。
**ジャッジの確認**　選択肢が実際に利用できるか、自律性をなぜ重視するか。
**メタ**　主次元 value_relevance｜B 2段｜予想攻撃 S04・I07・T03｜★★★｜低

#### L08　長期波及・正の循環型AD
**組み立て**　初期改善→継続を支える仕組み→長期的な利益。
**例・使い方**　参加経験が次の学習の継続を支える。
**ジャッジの確認**　途中のリンク・時間・脱落条件を証明。単なる楽観的連鎖にしない。
**メタ**　主次元 timeframe｜B 4段以上（例外）｜予想攻撃 C07・S07・I04｜★★★｜低

### DA（否定側の弊害）

#### L09　資源圧迫・機会費用型DA
**組み立て**　現状の資源配分→政策に資源が必要→別活動の縮小→損失。
**例・使い方**　維持管理に人員が移り、既存の支援が減る。
**ジャッジの確認**　「費用がかかる」だけでなく、何を失うかと移転の必然性。
**メタ**　主次元 severity｜B 3段｜予想攻撃 P05・C01・S03と混同注意｜★｜高

#### L10　行動の逆効果型DA
**組み立て**　現状の行動→政策が誘因を変える→望ましくない反応→被害。
**例・使い方**　支援の設計により、自力で取り組む時間が減る。
**ジャッジの確認**　想像だけで行動を断定しない。対象・条件・反応を裏づける。
**メタ**　主次元 probability｜B 3段｜予想攻撃 C03・C04・S04・I02｜★★｜中

#### L11　新しい危険の発生型DA
**組み立て**　現状で抑えられる危険→政策が露出を増やす→被害。
**例・使い方**　扱う情報が増え、管理上の危険が広がる。
**ジャッジの確認**　政策なしでもある危険との差。一般的な危険を政策固有に見せない。
**メタ**　主次元 probability｜B 2〜3段｜予想攻撃 P05・P06・I02｜★★｜中

#### L12　格差拡大・排除型DA
**組み立て**　現状の参加条件→政策が一部層に不利→機会の損失。
**例・使い方**　利用条件の違いにより、一部の生徒が参加しにくくなる。
**ジャッジの確認**　誰がどう不利になるか。平均効果と分配を分ける。
**メタ**　主次元 equity｜B 2〜3段｜予想攻撃 I06・I01・M02｜★★｜中

#### L13　権利・自由の制約型DA
**組み立て**　現状で認められる選択→政策による制約→その重み。
**例・使い方**　一律の手段を義務化し、事情に合う選択が失われる。
**ジャッジの確認**　何が制約され、なぜ重大か。権利という語だけで優位にしない。
**メタ**　主次元 value_relevance｜B 2段｜予想攻撃 I03・I07・T03｜★★★｜低

#### L14　既存制度の機能喪失型DA
**組み立て**　現在有効な仕組み→置換・撤去→機能が失われる→被害。
**例・使い方**　対面支援を廃止して置き換えると、個別支援を失う。
**ジャッジの確認**　元のプランが本当に置換を伴うか。追加提供へ架空の廃止を付けない。
**メタ**　主次元 severity｜B 2〜3段｜予想攻撃 R05（対象違い）・P05｜★★｜中

#### L15　不可逆・長期固定化型DA
**組み立て**　政策→戻しにくい変化→長期の損失。
**例・使い方**　特定方式への依存が強まり、後に変更しにくくなる。
**ジャッジの確認**　戻せない理由・期間・程度。単なる変更費用と不可逆性を分ける。
**メタ**　主次元 reversibility｜B 3段｜予想攻撃 I05・C07・I02｜★★★｜低

#### L16　Case flip・AD阻害型DA
**組み立て**　政策→逆方向の作用→相手が改善したい問題の悪化。
**例・使い方**　利用の効率化のはずが、確認作業を増やして負担を増す。
**ジャッジの確認**　新DAとして立論で証明。ADと結びつく破壊経路も適時に説明。
**メタ**　主次元 severity｜B 3段｜予想攻撃 R05・S08と混同注意｜★★★｜低

> **L16の重要な注記（v02で追加）**：L16は攻撃資料の**T04（Case flip）およびT05（DA turns case）と同一の実体**である。攻撃側の視点では「反転」、立論側の視点では「型」というだけで、試合に出るのは一つの議論である。
>
> **アプリでは二重に登録しない。** L16として立論に出た場合は `argument_groups.construction_pattern_id = 'L16'` を持つDAとして登録し、`clash_events` には T04/T05 を作らない。逆に、Attackの段階でT04が出た場合は、Rule State Engine が `INADMISSIBLE_NEW_DA` の候補として扱う（価値だけの反転T03は別）。

## 8. 証拠・理由づけ・数値（v01から継承）

### 8.1 一つの論点に四つの部品

| 部品 | 役割 |
| --- | --- |
| Claim｜主張 | 対象者の練習機会が増える |
| Evidence｜証拠 | 対象者の障壁や、類似条件での利用行動を示す資料 |
| Warrant｜理由づけ | 政策が障壁を除き、利用行動が変わるため機会が増える |
| Impact｜意味 | これまで機会を持たなかった対象者に、継続的な参加が可能になる |

Evidenceは理由づけの代わりにならない。「研究者が言った」だけでなく、その結果をこの政策・対象へ適用できる理由を説明する（E08の予防）。

### 8.2 引用前の点検

著者・機関、専門性、発表時期、対象、比較条件、調査方法、原文の限定、結論との対応。翻訳・要約で「可能性」を「確実」に変えない（E06の予防）。原文の該当ページと出所を保存する。

### 8.3 独自計算は一律禁止ではない

第20回規則§3.2.1.1では、独自計算であること、計算に用いる全データの出典、計算方法を口頭で明示することが求められる。独自推計を原典のエビデンスと偽らないことが重要（M07）。

### 8.4 不明な数字を作らない

例文中の［出典］［年度］［結果］は記入欄である。未確認の数字や架空の研究者名を入れて完成原稿にしない。分からない場合は、証明できる程度へ主張を限定する。

## 9. 原稿テンプレートと時間配分（v01から継承）

### 肯定側

> We support the motion. Our plan is [plan within the definition]. Our first advantage is [short label]. Without the plan, [problem]. According to [source and required details], [finding]. The plan changes this because [mechanism]. This leads to [result]. This matters because [**value dimension**]. Therefore, compared with the situation without the plan, [additional benefit].

### 否定側

> We oppose the motion. Our first disadvantage is [short label]. Without the plan, [baseline]. The plan would change this by [link]. According to [source and required details], [finding]. This leads to [harm] because [internal link]. This harm matters because [**value dimension**]. Therefore, the plan creates [additional harm].

`[value dimension]` は§5の8次元から選んだものを入れる（v02で明示）。

### 4分の配分例（練習用・公式配分ではない）

| 時間 | 肯定側 | 否定側 |
| --- | --- | --- |
| 0:00〜0:25 | 立場・プラン | 立場・DAの見取り図 |
| 0:25〜1:55 | AD1の証明 | DA1の証明 |
| 1:55〜3:25 | AD2の証明 | DA2の証明 |
| 3:25〜4:00 | 残る条件・結論 | 比較上の意味・結論 |

一本構成ならその証明に時間を回す。初心者は語数上限に近づけるより、短い文と間を優先する。

> **600語超過の扱い（v03で正確化）**　R1 §2.1.10 は、スピーチの速さを平均して1分あたり150語程度を越えてはならないとし、立論は最大600語までとしている。立論が600語を超えていると考えられる場合、ジャッジは全スピーチ終了後に原稿を求めて語数を確認することが**でき**、超過している場合はコミュニケーション点を減点**できる**だけでなく、600語を超過している部分で述べられたことを無視して判定を出すことが**できる**。
>
> つまり自動的な失格でも自動的な無効化でもなく、**ジャッジの裁量**である。アプリでは `rule_flags.over_word_limit` を候補として立てるだけにし、自動で判定材料から外さない。

## 10. 記録項目（v02で新設）

立論から生成する記録。アプリの列と1対1で対応する。

| 記録項目 | 内容 | アプリの列 |
| --- | --- | --- |
| 論点ID | AD1／AD2／DA1／DA2 | `argument_groups.label` |
| 構築型 | L01〜L16（複数可、NULL可） | `construction_pattern_id[]` |
| A｜現状 | 政策なしの状態と根拠 | `argument_nodes` (A_OBSERVATION) |
| B1..Bn｜因果 | 矢印ごとに1ノード | `argument_nodes` (B_LINK, `link_order`) |
| C｜重要性 | 結果の重大さ | `argument_nodes` (C_IMPACT) |
| Impact主次元 | §5の8次元から1つ | `impact_dimension_primary` |
| Impact副次元 | 最大2つ | `impact_dimension_secondary[]` |
| 成立範囲 | 誰に、どの条件で、どの程度 | `scope_note` |
| 証拠 | 出典・該当箇所・適用理由 | `evidence_refs` + `support_tags` |
| 独立性 | 他の論点との重複 | `overlap_with_issue_id` / `overlap_ratio` |
| 根拠位置 | 発言の時刻 | `segment_ids`（必須） |

**必須制約**：すべてのノードは `segment_ids` を1件以上持つ。原発言へ戻れないノードは判定材料にできない。

## 11. ジャッジは立論のどこを見るか（v01から継承・v02で1行追加）

| 確認項目 | 成立を支える説明 | 弱さが残る例 |
| --- | --- | --- |
| 論題・プラン | 定義に適合し条件が明確 | 対象外の政策から利益を得る |
| 現状・増分 | 政策なしとの差が明確 | 今ある問題を全て解決分と扱う |
| 因果・解決性 | 各接続と必要条件を説明 | 政策と最終結果の間が抜ける |
| 証拠・理由 | 対象と主張に合う根拠 | 原文にない結論を引用扱い |
| 重要性 | **どの次元で**、誰にどれだけ重要か（v02） | 「大切」で説明が終わる／次元が定まらない |
| 範囲・限界 | 条件・不確実性を明示 | 一例から全員へ一般化 |
| 独立性 | 各AD／DAの価値が独立 | 同じ利益を二度加算 |
| 伝わり方 | 聞いて論点を記録できる | 早口で出典・接続が届かない |

### Probability・Value・Strengthへの接続

Probabilityは、事実と証拠によって論点が構築・防御されたかを見る欄。ValueはImpactが説明・防御されたかを見る欄。Strengthはその両面を踏まえた強さ。**立論を聞いた段階は暫定記録**で、最終評価は攻防後。

「Probability × Value ＝ Strength」は判断の整理であり、公式の固定0〜10点尺度が指定されているわけではない。原因・証拠・人数の同じ欠陥を何度も別項目で減点しない。

### 未攻撃なら満点か

いいえ。相手が攻撃していなくても、必要な接続や価値の説明が不足すればその不足は残る。ただしジャッジが自分だけの専門知識から新しい反論を作り、発言者の代わりに試合へ加えることもしない。

## 12. 教材としての使い方（v02で新設）

### 12.1 学習順序

| 段階 | 扱う型 | 目標 |
| --- | --- | --- |
| 第1段階 | **Starter 3**（L01・L02・L09、§6） | A→B→Cの3ノードを、矢印ごとに理由を付けて書ける |
| 第2段階 | L03〜L06・L10〜L12 | Impactの次元（§5）を1つ選び、その次元で証明できる |
| 第3段階 | L07・L08・L13〜L16 | 多段リンク、価値の主張、反転型を、脱落条件つきで書ける |

**L08・L15・L16は初心者に勧めない。** どれも多段のBリンクか、価値の直接主張を含み、C07（飛躍）やR05（対象違い）で崩れやすい。

### 12.2 混同しやすい型の対

| 対 | 見分け方 |
| --- | --- |
| L01 と L03 | 問題が**既に起きている**ならL01、**これから起き得る**ならL03 |
| L04 と L05 | 減らすのが**時間・コスト**ならL04、上げるのが**能力・質**ならL05 |
| L06 と L12 | 格差を**縮める**主張はL06（AD）、**広げる**主張はL12（DA） |
| L09 と L14 | 資源が**他へ移る**ならL09、機能が**消える**ならL14 |
| L11 と L15 | 新しい**危険**ならL11、戻せない**固定化**ならL15 |
| L16 と 攻撃T04 | **同一実体**。立論で出せばL16、Attackで出せばT04（新DA相当の判定を受ける） |

### 12.3 練習課題

1. 同じ政策から、AD1（L02型）とDA1（L09型）を作る。両方が同時に成立し得ることを確認する。
2. 作ったAD1に対し、§5の8次元のうち**主次元を1つ**選び、なぜその次元なのかを一文で書く。
3. 予想攻撃IDを3つ挙げ、**プランを変更せずに**答えられるか確認する。答えられない場合、立論のどこに何を足すべきかを書く。
4. AD1とAD2の独立性を§1.1の三つの確認で点検する。依存していたら一本に統合する。

### 12.4 AIや指導者への渡し方

文章全体の印象点ではなく、「AD1のどの接続が不足しているか」をノードIDで指定して修正を求める。原典を追跡できるよう出典と引用箇所を保持し、AIが補った事実・数字は人が原典確認するまで証拠として使わない。試合中の利用可否は大会規則に従う。

## 13. アプリ側の実装メモ（v02で新設）

本書がai-debate-analyzerへ供給する定義。

| 供給先 | 内容 | フェーズ |
| --- | --- | --- |
| `construction_pattern_master` | L01〜L16（16行）。family, 標準B段数, 主次元, 予想攻撃ID, 難易度, starter フラグ | Phase A（列とマスタ） |
| `argument_groups.construction_pattern_id[]` | 型の付与（NULL可・複数可） | Phase A（列のみ）／Phase B（運用） |
| `argument_nodes.impact_dimension_primary` | §5の8値enum（`occurrence_likelihood` を含む） | **Phase A必須** |
| `argument_nodes.impact_dimension_secondary[]` | 同上 | Phase A |
| `argument_nodes.scope_note` | 成立範囲 | Phase A |
| `issue_snapshots.overlap_with_issue_id` / `overlap_ratio` | 二重計上の候補 | Phase A（列のみ） |
| AI抽出プロンプト | 型ごとの標準ノード構成 | Phase B |
| `rule_flags` の完全性候補 | 標準段数からの逸脱 | Phase B |

**判定式には入れない。** 構築型・難易度・頻出度はいずれもラベルであり、`Strength = P × V` の入力にしない。型で有利不利をつけると規則外の採点になる。

**impact_dimension を Phase A 必須とする理由**：C_IMPACTノードに次元がないと、攻撃側のI01〜I08が8つとも同じ `NOT_IMPORTANT` に潰れ、「人数が少ない」と「回復可能だ」が計算上同一に扱われる。後から列を足すとデータ移行が必要になる。

## 付録A. 注釈ガイドライン（立論部分）

実試合3〜10本へのID付与で、立論について確認すること。詳細な手順と指標は v03-攻撃 付録A を正本とする。ここでは立論固有の注意だけを書く。

### A.1 付与するもの

| 対象 | 付けるID | 一致率の目標 |
| --- | --- | --- |
| 論点（AD1/AD2/DA1/DA2） | L01〜L16（複数可、NULL可） | 0.6 |
| Aノード・Bノード・Cノードの切り出し | ノード境界 | **0.8（最重要）** |
| Bノードの段数と順序 | `link_order` | 0.7 |
| Cノード | `impact_dimension_primary` | 0.7 |
| 成立範囲 | `scope_note` の有無 | 0.9 |
| 論点の独立性 | `overlap_ratio` の粗い判定（重複あり／なし） | 0.8 |

### A.2 ノード分解が最優先である理由

**ここが合わないと、攻撃・防御・総括のIDがすべてずれる。** 攻撃のIDは「どのノードを狙ったか」とセットで意味を持つので、Bリンクを2段と数えるか3段と数えるかで、C02の `link_order` が変わり、防御の `parent_event_id` も変わる。

したがって付与作業では、**立論のノード分解を2人で行って突き合わせ、合意してから先へ進む**。ここを飛ばして各人が最後まで付けると、比較できない結果が2組できるだけになる。

### A.3 立論固有の割れやすい点

| 割れ方 | 判断の指針 |
| --- | --- |
| Bを何段に切るか | **話者が理由を述べた回数**で切る。理由なしにつないだ箇所は1段として扱い、C07（飛躍）の候補にする |
| L型が複数当てはまる | 複数可。ただし主たる型を1つ決める |
| L16かT04か | **立論で出たならL16**。Attackで出たならT04（攻撃側で記録） |
| AD1とAD2が独立か | §1.1の3つ目（片方が崩れたとき他方が独立に残るか）で判定する |
| `impact_dimension` が定まらない | 話者が次元を特定していない可能性が高い。「未特定」として残す。無理に1つへ寄せない |

**「未特定」を残すことが重要である。** 立論が次元を言っていないなら、それは記録すべき事実であって、注釈者が補うものではない。
