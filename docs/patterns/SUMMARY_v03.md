## v02から何を変えたか（参照用）

**観点1：アプリへ組み入れる**
v01の比較軸は8つ挙がっていたが、ai-debate-analyzer 側の `ComparisonAxis` は4軸（magnitude / probability / timeframe / value）しかない。v02では**8軸で確定**し、両者を一致させる（§5）。

さらに、G01〜G16のうち **G10・G14は論点間の関係**を扱う。これは「Issue i だけを立論終了時へ戻し、他は最終値のまま」という反実仮想（`clash_leverage`）が前提とする論点の独立性を壊す。したがって**説明専用として記録し、数値モデルは参照しない**ことを明示した（§4.3）。

**観点2：教材としての有効性**
G01〜G16を「型」として16個並べるだけでは、試合中に選べない。**選択のフローチャート**（§7）を新設した。また、総括で最も多い失敗である「立論の再読」「新規議論の混入」を、判定側の検査手順と対にした。

**内容面の主な追加・変更**

| # | 追加・変更 | 理由 |
| --- | --- | --- |
| 1 | **比較軸を8軸で確定**（§5） | v01は8つ挙げていたがアプリ側は4軸。攻撃W系・I系と対応が取れていなかった |
| 2 | **impact_dimension と comparison_axis を別物として定義**（§5.1） | 単一Impactの内訳と、2つを比べる軸は違う。混ぜると二重評価になる |
| 3 | **G10・G14 を `issue_relation`（説明専用）に限定**（§4.3） | counterfactual の独立性仮定を守る |
| 4 | **G12・G16 に `concession_mode` を必須化** | 「仮に認めても」を事実承認として記録すると、実際より低い値で確定する |
| 5 | **G11・G16 に `residual_scope` を必須化** | 残存範囲が記録されていないと比較が再現できない |
| 6 | **W04（二重計上）の検査手順**（§6.3） | net sum モデルへの攻撃。立論段階の予防と対にする |
| 7 | **Double turn の確認をG13に組み込み**（§4.4） | v01は深掘りに書かれていたが、総括の判断手順に入っていなかった |
| 8 | ジャッジ8手順を L1／L2／L3 に対応づけ（§9） | 公式判定層・内部分析層・学習可視化層を混ぜない |
| 9 | 型の選択フローチャート（§7） | 教材として |

**変えていないこと**：総括の役割と時間、新規議論の禁止、G01〜G16の内容、判定は固定配点へ変換しないという原則。

## 1. 総括の役割とHEnDAの境界

| 項目 | 判断と実践 |
| --- | --- |
| 肯定総括 | 3分。双方のAD／DAと攻防を要約し、ADがDAを上回る理由を述べる |
| 否定総括 | 3分。双方のAD／DAと攻防を要約し、DAがADを上回る理由を述べる |
| 新しい論点 | 新プラン・新AD／DA・相手への新Attackは追加しない |
| 正当な比較 | 既出議論をより深く比較する観点や、細かな証拠比較は新規攻撃と区別する |
| 後発の証拠 | 新しい証拠というだけで一律排除せず、その役割が新Attackなのか既出議論の比較なのかを確認 |

根拠：R1 §§2.1.7〜2.1.8、4.2.2。新規性は語句が初出かだけでなく、命題・因果・価値・相手に求める新しい応答で判断する。

### 1.1 総括の四つの部品

| 部品 | 答える問い | アプリの列 |
| --- | --- | --- |
| **Clash｜争点** | 勝敗を分ける、何についての対立か | `comparison_events.clash_label` |
| **攻防の帰結** | 相手はどこを攻撃し、自分はどこまで守ったか | `clash_events`（既存） |
| **残存価値** | 対象・確実性・程度を限定すると、何が残るか | `residual_scope` |
| **Comparison｜比較** | 残るADとDAを、どの基準でなぜ比べるか | `comparison_events`（軸＋理由） |

### 1.2 総括とDefenseを区別する

Defenseの中心は自分のAD／DAの再構築。総括はその結果を含む全体比較。守れなかった部分を立論時の強さに戻して読まず、相手の有効な攻撃・限定承認を反映させる。

> **比較は総括の専売ではない（v03で追加）**　R1 §2.1.5・§2.1.6 は、肯定・否定いずれのディフェンスでも、相手側に直接アタックを付け加えるのでないならば、今までの議論の比較をする観点を出すことは許されるとしている。側注はこれを、守ることに主眼を置いた間接的な攻めであり総括につながるので**推奨される**とまで書いている。
>
> 違うのは**役割の重心**である。ディフェンスは再構築が役割で比較は付随、総括は比較が役割である。したがってアプリの `comparison_events` は⑨〜⑫を横断して記録し、`stage_no` で区別する。詳細は v03-防御 §1.1。

### 1.3 否定側の最後の発言

否定側は最後に話せるからこそ、新しい事実や被害を追加しないことが重要。肯定総括の比較に対しても、既出の論点・証拠・条件を使い、どの比較が妥当かを説明する。

## 2. フローから「残った論点」を取り出す

### 2.1 準備時間に埋める四つの欄

| 論点 | 攻撃の要点 | 防御の要点 | 残るもの |
| --- | --- | --- | --- |
| AD1 | どの証拠／接続／価値を崩したか | どこに直接答えたか | 対象・効果・価値の残存範囲 |
| AD2 | 独立した攻撃を区別 | 未応答も記録 | 重複しない追加利益 |
| DA1 | 非固有性・リンク等 | 政策が増やす被害を再確認 | 実際に残る追加被害 |
| DA2 | 価値・規模等 | 限定承認や反転への応答 | 残る被害と比較上の意味 |

発言順の全てを読み上げる必要はない。総括では勝敗に影響する接続を選ぶ。

### 2.2 残存状態の読み分け（v02で拡張）

| 状態 | 意味 | アプリの表現 |
| --- | --- | --- |
| 未攻撃 | 攻撃イベントが無い | `clash_events` なし |
| 攻撃されたが防御済み | 核心に答え、回復した | `recovery_cat ≥ Substantial` |
| 部分的に弱まった | 一部のみ回復 | `recovery_cat = Partial` + `residual_scope` |
| 不可欠な接続が崩れた | Bリンクが切れた | `recovery_cat ≤ Minor`、対象ノードが `NO_EFFECT` |
| **攻撃は成立するが影響しない** | 別の根拠で結論が立つ（D10） | `recovery_cat = Immaterial`（v02で追加） |
| 価値が反転した | Value turn が残った | `impact_direction = -1` |
| 新規性により除外 | 適時性の問題 | `rule_state = INADMISSIBLE_*` |
| **記録が無い／聞き取れない** | 判定材料にしない | `stage_coverage_gap` / `audibility_gap`（v02で明示） |

未応答だけで自動成立、総括で名称が出なかっただけで機械的にゼロ、という処理はしない。

> **最後の行が重要**　「記録が無い」「聞き取れなかった」を「答えなかった」として扱わない。この三つは画面上どれも同じ空白に見えるが、判定でできることが違う。DROPSだけが判定材料になり、他の二つはならない。

### 2.3 根拠の位置を残す

「DA1に対する肯定Attackの指摘」のように側と対象を明示する。ADは否定Attack→肯定Defense、DAは肯定Attack→否定Defenseの流れで記録する。必要な引用・時刻・発言者の役割を残し、AIの要約だけで判定を確定しない。

### 2.4 争点の選び方

双方が同意する一般論ではなく、対立を選ぶ。「教育は大切か」ではなく「対象生徒へ実際に届くか」「管理負担が支援の減少を起こすか」「残る機会改善と支援喪失のどちらが重いか」。

## 3. binding：総括の型が「どこへ効くか」（v02で新設）

攻撃資料と同じ考え方で、G01〜G16にも写像先を付ける。

| binding | 意味 | 該当 | 件数 |
| --- | --- | --- | --- |
| `comparison` | 比較軸を選び、理由を付ける。ノード値は動かない | G03〜G09・G15 | 8 |
| `issue_selection` | どの論点を争点にするかの選択 | G01・G02 | 2 |
| `residual` | 残存範囲を確定し、その価値を比較する | G11・G16 | 2 |
| `issue_relation` | 論点間の関係。**説明専用・数値モデル非参照** | G10・G14 | 2 |
| `concession` | 仮定承認を明示したうえでの比較 | G12 | 1 |
| `turn_use` | 既出の反転を比較へ持ち込む | G13 | 1 |

**合計16。**（v02では comparison を9と誤記し合計が17になっていた。G03〜G09が7、G15が1で8が正しい。）

**すべてのGは `Strength = P × V` の入力にならない。** 総括は比較の主張であり、ノードの成立度を動かすものではない。

## 4. 総括・比較のパターン G01〜G16

```
組み立て　構成
例・使い方　仮想例
ジャッジの確認　成立を見るポイント
メタ　binding｜使う比較軸｜必須属性｜難易度｜頻出度
```

### 4.1 争点の選択と基本の比較（G01〜G04）

#### G01　決定的争点集中型
**組み立て**　最も勝敗を分ける一つの争点→攻防結果→比較→結論。
**例・使い方**　AD1の解決性が残るかを先に確定する。
**ジャッジの確認**　争点を絞っても、相手の別の強いDAを無視していないか。
**メタ**　issue_selection｜軸=文脈依存｜★｜高

#### G02　二争点整理型
**組み立て**　成立の確かさと価値など、二つの独立した争点で整理する。
**例・使い方**　「本当に起きるか」「起きた場合に何が重要か」を分ける。
**ジャッジの確認**　同じ理由を言い換えて二度勝った扱いにしない。
**メタ**　issue_selection｜軸=probability＋severity｜★★｜高

#### G03　同一指標比較型
**組み立て**　対象・期間・単位を揃え、同じ結果を比べる。
**例・使い方**　双方が学習時間を論じるなら、質や対象も合わせる。
**ジャッジの確認**　数字が同じ単位でも中身が同じか。重複や対象差も点検。
**メタ**　comparison｜軸=scale｜★｜高

#### G04　異なる価値の比較型
**組み立て**　異なる利益を認める→共通の判断原理→優先理由。
**例・使い方**　利便性と個別支援を、影響の深刻さと代替可能性で比べる。
**ジャッジの確認**　自分に有利な価値を宣言するだけでなく、基準を正当化したか。
**メタ**　comparison｜軸=severity＋substitutability｜★★★｜中

### 4.2 比較軸を明示する型（G05〜G09・G15）

#### G05　実現確実性重視型
**組み立て**　大きさに加えて成立する根拠を比較する。
**例・使い方**　大きいが接続未証明の効果と、小さくても根拠がある効果を比較。
**ジャッジの確認**　**Probabilityと規模を混同しない。** 根拠のない確率を作らない。
**メタ**　comparison｜軸=**probability**｜★★｜高

#### G06　規模・深刻さ重視型
**組み立て**　起きる範囲を整理→一人当たりの負担→総合的な意味。
**例・使い方**　多数の軽微な不便と、少数の重大な参加困難を比較する。
**ジャッジの確認**　人数だけで結論を出さず、価値の理由を説明しているか。
**メタ**　comparison｜軸=**scale＋severity**｜★｜高

#### G07　時間・持続性重視型
**組み立て**　発現時期・期間を揃え、短期負担と長期利益を比較。
**例・使い方**　初期の準備負担と、複数年度の機会改善を比べる。
**ジャッジの確認**　将来利益を無条件に継続と仮定せず、根拠と条件を確認。
**メタ**　comparison｜軸=**timeframe**｜★★｜中

#### G08　不可逆性・回復可能性型
**組み立て**　損失を戻せるか→回復までの負担→優先理由。
**例・使い方**　一時的な手間と、回復が難しい機会喪失を比べる。
**ジャッジの確認**　「取り返せない」という標語でなく、その理由が示されたか。
**メタ**　comparison｜軸=**reversibility**｜★★｜中

#### G09　公平性・分配型
**組み立て**　誰が利益を得て誰が負担するか→格差への作用→比較。
**例・使い方**　平均改善より、支援を失う層の重大な不利益を示す。
**ジャッジの確認**　総量との関係を説明し、少数だから自動勝利にしていないか。
**メタ**　comparison｜軸=**equity**｜★★★｜中

#### G15　証拠比較で解く型
**組み立て**　双方の証拠の対象・方法・時期→適用性→帰結。
**例・使い方**　今回の対象に近い比較研究と、条件の違う事例を比較する。
**ジャッジの確認**　引用数で競わず、勝敗に関係する証明力の差を説明したか。
**メタ**　comparison｜軸=probability（Support Quality経由）｜★★★｜中

### 4.3 論点間の関係を使う型（G10・G14）

> **v02での重要な制限**　G10とG14は、論点と論点の関係を主張する。判定理由を書くには欠かせないが、**アプリの数値モデルには入れない。**
>
> 理由：`clash_leverage` の反実仮想は「Issue i のA/B/Cのみ立論終了時へ戻し、他Issueは最終値のまま」で成り立っている。Issue間に依存があると、この独立性仮定が崩れ、counterfactual が意味を失う。また `aff_sum = Σ Strength` の加算も成立しなくなる。
>
> したがって `issue_relations` テーブルに**説明専用**で記録し、`official_decision_support` の計算経路はこれを参照しない。CIで静的検査する。人間ジャッジが判定理由の中で使うことは、当然ながら自由である。

> **UI要件（v03で追加）**　この二層構造は、画面上で見えないと誤用される。`issue_relations` から導かれた記述は、Clash View・判定理由エディタのいずれでも **「説明専用（判定計算には反映されません）」** のラベルを添えて表示する。ラベルなしで他のイベントと同じ見た目にすると、「AIがこの関係を勘定に入れて勝者を出した」と読まれる。
>
> あわせて、`clash_leverage` の counterfactual 結果を表示する画面では、**論点の独立性を仮定している**旨を注記する。G10/G14の関係が強い試合では、この仮定自体が弱いためである。

#### G10　前提条件優先型
**組み立て**　一方の価値が他方の成立に必要だと示す→先に守る理由。
**例・使い方**　参加できる状態を確保して初めて、教材の質が意味を持つ。
**ジャッジの確認**　その前提関係が既出論点から導けるか。**新しい因果を作らない。**
**メタ**　**issue_relation（説明専用）**｜軸=prerequisite｜★★★｜低
**対応攻撃**　W05

#### G14　論点間の関係を使う型
**組み立て**　既出のDAがADを阻害する等の関係→比較への影響。
**例・使い方**　既に証明された人員喪失が、既出の支援ADも弱める。
**ジャッジの確認**　接続が試合内にあり、**同じ損失を二度数えていないか。**
**メタ**　**issue_relation（説明専用）**｜★★★｜中
**対応攻撃**　T05・T06

### 4.4 残存・承認・反転の型（G11〜G13・G16）

#### G11　部分残存・最低限確保型
**組み立て**　攻撃で減った部分を認め→確実に残る範囲→その価値。
**例・使い方**　全生徒への効果でなく、特定の未参加層への利益を比較する。
**ジャッジの確認**　範囲を狭めても同じADか、**新しい対象・価値へのすり替え**か。
**メタ**　residual｜**`residual_scope` 必須**｜★★｜高
**対応防御**　D07・D08

> **すり替えの検査**　狭めた後の対象が、立論時の `scope_note` の部分集合であることを確認する。部分集合でなければ、新ADへの変更（R03）の候補になる。

#### G12　仮に認めても型／Even if
**組み立て**　主位的な応答→相手を仮定で受け入れる→それでも上回る。
**例・使い方**　費用DAを認めたとしても、既出の重大な支援利益を重視する。
**ジャッジの確認**　仮定の承認範囲と比較根拠が明確か。単なる勝利宣言ではないか。
**メタ**　concession｜**`concession_mode = arguendo` 必須**｜★★｜高
**対応攻撃・防御**　W08・D16

> **v02での最重要注記**　「仮に認めても」は事実の承認ではない。これを `concede` として記録すると、実際には否定している論点についてノード値を下げて確定してしまう。画面上はきれいに埋まって見えるので、誰も気づかない。
>
> 発話上の要件：Even if / 仮に認めても、を明示的に言う。言わずに比較へ移ると、ジャッジは事実承認と区別できない（防御資料 X06）。

**規則の根拠（v03で追加）**　R1 §2.1.7・§2.1.8 の側注は、総括では攻撃できなかった相手のAD／DAへのアタックは許されないが、**「相手の議論を認めたとしても、私たちのAdvantage／Disadvantageには劣る」というような比較は許される**と明記している。G12はここに直接の根拠がある。同じ側注は、なぜ自陣が上回るかという価値比較基準についての主張を「重要な比較であり、むしろ積極的に奨励される」ともしている。

#### G13　反転を活用する型
**組み立て**　適時に提出された反転→防御後の残存→自分側の支持理由。
**例・使い方**　既出のValue turnが残るなら、同じ結果の評価が逆になると示す。
**ジャッジの確認**　総括で初めて反転を発明していないか。**Double turnの矛盾も確認。**
**メタ**　turn_use｜`impact_direction`｜★★★｜低
**対応攻撃**　T01〜T05

> **Double turn の確認（v02で判断手順に組み込み）**　同一論点に対し同じ側が「政策はXを減らす」（Link turn）と「Xは良い」（Value turn）を**事実として**同時主張していると、「政策は良いものを減らす」となり自分に不利になる。
>
> アプリでは、同一 `target_argument_id` に同一側から `T01/T02` と `T03` の両方が `ADMISSIBLE` かつ `concession_mode = factual` で存在する場合、`rule_flags.double_turn` を候補として立てる。**自動除外はしない。** 判定への影響は人が決める。
>
> **反転が残る論点は、黙って撤回しても消えない。** 撤回する前に解除（D12）が要る。

#### G16　限定承認・純利益型
**組み立て**　相手の成立部分を公平に認め→重複を除く→残る全体を比較。
**例・使い方**　AD1とDA1をともに認めたうえで、追加分と重要性を比べる。
**ジャッジの確認**　機械的足し算ではなく、残る価値と比較理由が明示されたか。
**メタ**　residual｜**`residual_scope`・`concession_mode` 必須**｜★★★｜中

## 5. 比較軸を8つで確定する（v02で確定）

### 5.1 二つの列は別物である

**混同しやすいので先に区別する。**

| | `impact_dimension` | `comparison_axis` |
| --- | --- | --- |
| 何を表すか | **一つのImpactの内訳**。この利益・被害はどの意味で重要か | **二つのImpactを比べる軸**。ADとDAをどの基準で並べるか |
| どこで使うか | 立論（v03-立論 §5）、攻撃I系 | 総括（本書）、攻撃W系 |
| 誰が決めるか | 立論者。攻撃者はそれを狙う | 総括者。示されなければジャッジが決める |
| 値の数 | 8 | 8（6つは共通、2つずつ固有） |

**この二つを同じ列にすると、単一Impactの評価と比較の基準が同じ欄に混ざり、二重評価になる。**

### 5.2 `comparison_axis` の8値

| 軸 | 確認する問い | 注意 | 対応G | 対応W |
| --- | --- | --- | --- | --- |
| **scale｜規模** | 影響を受けるのは何人・どの範囲か | 重複人数を足さない | G03・G06 | W01・W03 |
| **severity｜深刻さ** | 一人に何がどの程度起きるか | 大きいという形容で済ませない | G06・G04 | — |
| **probability｜成立の確かさ** | どの条件・証拠が結果を支えるか | Probabilityを架空の％にしない | G05・G15 | W03 |
| **timeframe｜期間・時期** | いつ始まり、どれだけ続くか | 年額と総額を混ぜない | G07 | W02・W06 |
| **reversibility｜可逆性** | 元へ戻れるか、回復負担は何か | 可逆でも被害ゼロではない | G08 | W06 |
| **equity｜公平性** | 受益者と被害者は誰か | 平均だけで代表させない | G09 | W07 |
| **substitutability｜代替可能性** | 同じ利益を他でも得られるか | 新しい別政策を勝手に採択しない | G04 | — |
| **prerequisite｜前提関係** | 一方がなければ他方は成立しないか | 新しいリンクを総括で足さない | G10 | W05 |

### 5.3 `impact_dimension` の8値（参考・立論資料と共通）

scale／**occurrence_likelihood**／severity／timeframe／reversibility／equity／**value_relevance**／**marginal_utility**

`comparison_axis` と共通するのは scale・severity・timeframe・reversibility・equity の5つ。`comparison_axis` 固有は probability・substitutability・prerequisite、`impact_dimension` 固有は occurrence_likelihood・value_relevance・marginal_utility。

> **v03での名称変更**　v02では `impact_dimension` にも `probability` という値を置いていたが、HEnDA Judge Sheet の公式欄 **Probability**（そのIssueが事実・Evidenceによってどの程度成立したか）と同名で、アプリ内で混同する危険があった。`impact_dimension` 側を **`occurrence_likelihood`**（そのImpactが実際に起きる見込み）へ改名する。
>
> `comparison_axis` の `probability` は公式Probabilityと同じ概念なので、こちらは同名のままでよい。G05「Probabilityと規模を混同しない」も公式Probabilityを指している。

### 5.4 基準を採用する理由まで述べる

「公平性が大切です」では不足。比較対象と優先理由を結びつける。

> 「既出の議論では、同じ生徒にとって参加の入口を失うことと短い待ち時間が比較されている。参加できる状態は待ち時間の改善を享受する前提なので、入口を守る利益を重視する」

### 5.5 複数の軸が逆方向を向いたとき

人数はADが大きいが深刻さはDAが大きい、という場合もある。どちらかを消さず、その試合で示された根拠と価値の理由を使って比較する。**全軸で勝つ必要はない。** 自分に不利な軸を認めても、決定的な理由を説明できればよい。

### 5.6 比較基準を誰が持ち出したか

大会ルールの運用では、比較基準が試合中に示されなかった場合、ジャッジ独自の判断で比較評価してよいとされている。

- **ディベーター由来の比較**：根拠 `segment_ids` を必須にする
- **ジャッジ由来の比較**：segmentなしを許す代わりに、判定理由に「試合中に比較基準が示されなかったため、ジャッジの判断による」と明記する

> アプリでは `comparison_source ∈ {debater, judge}` で区別する。

## 6. 「新しい議論」と「深い比較」の境界

### 6.1 見分けるポイント

| 発言例 | 扱い |
| --- | --- |
| 総括で初めて「情報漏洩が起きる」 | 独立した新DA・新Attackなら除外対象 |
| 既出の費用DAと機会ADを期間で比べる | 既出議論の比較になり得る。期間の根拠を確認 |
| 既出証拠の対象年齢の違いを照合 | 細かな証拠比較として許容され得る。単に初出語で排除しない |
| 新たな通信補助金で解決できると言う | 元のプランにない施策なら、新プラン追加の問題 |
| 既出の価値を「仮に認めても」と比べる | 新しい攻撃を足さない比較として扱う |
| 既出ADを、別の集団・別の利益へ変更 | 同じ見出しでも新ADに相当しないか確認 |
| 新資料で別の因果経路を初めて攻撃 | 新Attackを証拠比較と呼び替えていないか確認 |
| 新資料が既出価値の比較だけを深める | R1 §4.2.2の正当な比較の範囲かを判断 |
| **ディフェンスへの再々反論にあたる議論** | **総括では細かい証拠比較として許される**（v03で追加） |

> **「細かい証拠比較」の具体例（v03で追加）**　R1 §2.1.7・§2.1.8 は、総括で許される「細かい証拠比較」の例として、**相手のディフェンスへの再々反論にあたる議論**を挙げている。
>
> これは重要な線引きである。ディフェンス段階では直前のディフェンスへの再々反論は禁じられている（防御資料 X07）が、**同じ内容が総括で出れば許される**。したがってアプリでは、同じ発言内容でもステージによって `rule_state` が変わる。X07は⑨⑩のディフェンス段階に限った禁じ手であり、⑪⑫の総括では `ADMISSIBLE_COMPARISON_MICRO` になり得る。

### 6.2 判断の四段階

元の発言がどこにあるか→その命題の意味を確認→今回増えたのは説明・比較か新しい主張か→相手に新たな反論の必要を生じさせるか。最後の問いだけで機械判定せず、役割と規則を併せて判断する。

新規性の判断は、相手の抗議があるかどうかだけに依存しない。ジャッジがR1 §4.2.2に基づき確認する。

> **アプリの Rule State**　`ADMISSIBLE_COMPARISON_MICRO`（細かな証拠比較）／`ADMISSIBLE_COMPARISON_MACRO`（既出論点の比較）／`ADMISSIBLE_NEW_EVIDENCE_FOR_COMPARISON`（比較のための新証拠）／`INADMISSIBLE_LATE_REPAIR`（欠けていた立証をSummaryで初めて完成）。
>
> `ADMISSIBLE_NEW_EVIDENCE_FOR_COMPARISON` は**比較説明とVoting Issue の理由づけには使えるが、A/B/Cノードの値を上げない。** これが「深い比較」と「後付け修復」を分ける線である。

### 6.3 二重計上の検査（v02で新設）

W04（二重計上）は総括の合計そのものへの攻撃である。次の三点で検査する。

1. **受益者が違うか**（同じ生徒か、別の集団か）
2. **改善する内容が違うか**（同じ「参加機会」を言い換えていないか）
3. **片方が崩れたとき、もう片方が独立に残るか**

3つ目が最も確実。AD1のBリンクが切れたときAD2も同時に崩れるなら、独立した二つではない。

> アプリでは `issue_snapshots.overlap_with_issue_id` / `overlap_ratio` に記録する。AIは重複候補までを出し、独立性の確定は人が行う。立論段階の予防は v03-立論 §1.1。

## 7. 型の選択フローチャート（v02で新設）

準備時間の1分でここを通る。

```
① 争点はいくつか
   1つに絞れる ─────────────→ G01
   2つある ───────────────→ G02
   
② 両側が同じものを論じているか
   同じ指標 ─────────────→ G03（軸を揃える）
   違う価値 ─────────────→ G04（判断原理を出す）

③ 何で差がつくか（軸を1つ選ぶ）
   起きるかどうか ─────────→ G05  axis=probability
   人数・深刻さ ──────────→ G06  axis=scale+severity
   いつ・どれだけ続くか ────→ G07  axis=timeframe
   戻せるか ─────────────→ G08  axis=reversibility
   誰が負担するか ─────────→ G09  axis=equity
   証拠の質 ─────────────→ G15  axis=probability

④ 自分の論点が削られているか
   範囲を狭めて残った ─────→ G11（residual_scope 必須）
   両方認めて差引き ───────→ G16（residual_scope + concession_mode）

⑤ 相手の論点が強いか
   仮に認めても勝てる ─────→ G12（concession_mode=arguendo 必須）
   反転が残っている ───────→ G13（Double turn を確認）

⑥ 論点どうしがつながっているか
   前提関係がある ─────────→ G10  ※判定理由の説明用
   一方が他方を壊す ───────→ G14  ※判定理由の説明用
```

**併用が普通である。** 実際の総括は「G11＋G06＋G12」のように3つ程度を組み合わせる。型を1つに決めることが目的ではない。

## 8. テンプレートと3分の配分

### 8.1 共通テンプレート

> The key issue is [clash]. They argued [attack]. We answered [defense and reason]. Therefore, [what remains]. Their strongest remaining point is [opposing issue]. **Even if** we accept [limited assumption], our side should win because [comparison and **axis + reason**]. For these reasons, [AD/DA label] is the decisive issue.

日本語の骨組み：「争点はXです。相手はYを攻撃しましたが、こちらはZという理由で答えました。したがってAが残ります。相手に残る最も強い論点はBです。**仮に**Bを認めた**としても**、Cという比較理由からAを重視すべきです。」

**v02で明示した2点**：`Even if` を省略しない（G12・X06）。`[comparison]` には軸の名前と、その軸を選ぶ理由を入れる（§5.4）。

### 8.2 3分の配分（練習用・公式指定ではない）

| 時間 | 内容 |
| --- | --- |
| 0:00〜0:20 | 勝敗を分ける争点を提示 |
| 0:20〜1:10 | 重要な攻撃・防御と残存結論 |
| 1:10〜2:20 | 相手の強い論点との比較 |
| 2:20〜2:50 | 不利な仮定でも維持できる理由 |
| 2:50〜3:00 | 投票理由を一文でまとめる |

### 8.3 準備時間の優先順位

争点を二つ以内に絞る→各争点の**残存結論**を書く→相手の最強の論点を選ぶ→**比較軸と理由**を一つ以上書く→新規議論がないか確認する。

## 9. ジャッジの判断手順（v02で層を明示）

v01の8手順に、どの層の作業かを対応づける。**L1（公式判定層）・L2（内部分析層）・L3（学習可視化層）を混ぜない。**

| # | 手順 | 内容 | 層 |
| --- | --- | --- | --- |
| 1 | 対象論点を確定 | 実際に提出された主要AD／DAを確認。数の制限、論題逸脱、新規議論を点検 | L1＋L2 |
| 2 | 攻防を対応づける | どの攻撃がどこを狙い、どの防御が直接答えたかをフローで照合 | L2 |
| 3 | Probabilityを評価 | 現状・因果・解決性が、事実・証拠・理由づけと攻防を経てどこまで成立するか | **L1** |
| 4 | Valueを評価 | 残る結果の規模・深刻さ・期間・意味が説明され、防御されているか | **L1** |
| 5 | Strengthを整理 | 成立の確かさと価値を総合し、各論点の強さを理由つきで記す。**固定配点に変換しない** | **L1** |
| 6 | ADとDAを比較 | 双方が提示した比較基準を検討し、重複を除いて全体の優劣を判断。基準の宣言だけで採用しない | **L1** |
| 7 | Voting Issueを言語化 | どのAD／DAと、どの攻防・比較が投票を決めたかを一文で示す | **L1** |
| 8 | 別評価と手続を確認 | 英語の印象だけで決めていないか、新規論点を使っていないか。Communication Pointsは別 | L1＋L2 |

R1 §4.2では、接近していても細かな差を検討する。どう検証しても優劣をつけられないごく例外的な場合に推定（presumption）で否定側へ投票する。**「迷ったら否定」「肯定の証拠が100％でなければ否定」という基準ではない。**

### 9.1 AIが止まる条件（v02で明示）

次の場合、AIは一方の勝者を断定せず `REVIEW_REQUIRED` を出す。

- 重大な `UNVERIFIABLE` / 記録欠損が勝敗へ影響し得る
- Value turn の採否で勝者候補が変わる
- Voting Issue の survival 候補と clash 候補が競合し、説明の confidence が低い
- Summary の新Evidenceが comparison なのか late repair なのか境界的
- **Double turn の候補が立っており、その扱いで勝者が変わり得る**（v02で追加）

### 9.2 Voting Issue の二候補

- **survival_candidate**：最終時点で勝者側に残った論点のうち最も強いもの
- **clash_candidate**：その論点のclashを取り除いて立論終了時へ戻したとき、最終marginを最も大きく動かすもの

二つが一致すれば confidence は高い。一致しなければ両方を提示し、AIは暫定候補としてしか扱わない。勝者が反転するほど大きなclashだった場合は `winner_flip` として目立たせる。

> **G10・G14 がこの計算に入らない理由**（§4.3の再掲）：counterfactual は論点の独立性を前提にしている。

## 10. ジャッジシートと講評

| 欄 | 記録例／注意 |
| --- | --- |
| Probability | 「校内利用の対象では接続が残る。家庭利用は未証明」。Hi／Loの選択を理由に結びつける |
| Value（Impact） | 「参加の入口を得る利益。ただし対象限定」。Large／Smallを言葉で説明する |
| Strength | Strong／Weak／Noneの背景を示す。巨大な価値でも因果が切れれば強い論点にはならない |
| 比較・Voting Issue | 「AD1の参加改善が、DA1の限定的な待ち時間増加を**深刻さ（severity）**で上回る」。**軸の名前を書く**（v02） |
| New Arguments | 判定に使用した命題が、適切な段階で提出されたか確認 |
| Communication Points | チームの伝達を1〜5の整数で別評価。0点・小数点にしない |

掛け算や合計の図式を、未定義の固定数値へ機械変換しない。同じ欠陥をProbabilityとValueで重複減点することにも注意する。

### 10.1 Strength を None にするとき（v02で明示）

「小さい」と「ゼロ」は違う。Judge Sheet の上ではどちらも `None` と書けてしまう。**`None` にしたときは、何が残っていて、それでもなぜ勘定に入れないのかを必ず書く。** 書くのは点数ではなく理由である。

> アプリでは `residual_note` の無い `None` を保存できない。

### 10.2 講評の順序

勝者→決定的な比較→認めた論点→攻撃・防御の帰結→改善の助言。「実際の判定理由」と「試合に出なかった改善案」は明確に分ける。自分の政策の好みや別試合の記憶を、今回の証拠として持ち込まない。

### 10.3 コミュニケーション評価との区別

5は全体として非常に明瞭で聴衆と意思疎通ができる状態、3はおおむね伝わる状態、1は大半が伝わらない状態を基準に、R1 §4.3へ照合する。流暢さを論証の代わりに評価しない一方、実際に伝わらなかった論点を原稿から補って勝敗を決めることもしない。

> アプリでは判定理由の段落を content / comparison / procedure / delivery / advice に分ける。`delivery` の段落が Voting Issue の理由に使われていれば `communication_in_content` を候補として立てる。**自動除外はしない。**

## 12. 教材としての使い方

### 12.1 学習順序

| 段階 | 型 | 目標 |
| --- | --- | --- |
| 第1段階 | G01・G03・G06 | 争点を1つ選び、軸を1つ決めて比べられる |
| 第2段階 | G02・G05・G07・G08・G11・G12 | 残存範囲を言え、Even if を正しく使える |
| 第3段階 | G04・G09・G10・G13〜G16 | 価値の比較、反転、論点間の関係を扱える |

**G12（Even if）は第2段階に置く。** 早く教えると主位の応答を飛ばす癖がつくが、遅すぎると「相手の強い論点を無視する総括」から抜け出せない。

### 12.2 典型的な失敗を直す

| 失敗 | 直し方 |
| --- | --- |
| 立論の再読 | 攻防後の**残存結論**へ |
| 攻撃数の自慢 | 結論への**効果**へ |
| 自分の利益だけ | **相手の最強論点との比較**へ |
| 「重要です」の連発 | **対象と優先理由**へ |
| 後出しの事実 | **既出の根拠による比較**へ |
| 勝利宣言 | **Voting Issue**へ |
| 軸を言わない | **8軸から1つ選び、名前を言う**（v02） |
| Even if を言わない | **明示する**（v02・X06） |

### 12.3 練習課題

1. 与えられたフロー1本から、争点を2つ以内に絞る。
2. 各争点について、§5.2の8軸から1つ選び、なぜその軸かを一文で書く。
3. 自分側の残存範囲を、立論時の `scope_note` の部分集合として書く。部分集合でなければすり替え（R03）である。
4. 相手の最強論点に対してG12を作る。「仮に認めても」を明示的に発話する。
5. 反転を使った場合、Double turn になっていないか確認する。
6. 最後に、判定理由を一文で書く。「〇〇の理由で AD1／DA1 を重視する」。

### 12.4 学習・AI表示への応用

AD1／DA1ごとに元発言・攻撃・防御・総括の比較を連結する。**HP等は学習用の表示とし、公式のStrengthや勝敗と同一視しない。** 判定案は根拠位置を示し、人間が新規性と対応関係を確認する。

## 付録A. 注釈ガイドライン（総括部分）

実試合3〜10本へのID付与で、総括について確認すること。詳細な手順と指標は v03-攻撃 付録A を正本とする。

### A.1 付与するもの

| 対象 | 付けるID | 一致率の目標 |
| --- | --- | --- |
| 争点の切り出し | clash の境界 | 0.7 |
| 比較ごと | G01〜G16（複数可） | 0.6 |
| 比較ごと | `comparison_axis`（8値） | **0.8（最重要）** |
| 比較ごと | `comparison_source`（debater / judge） | 0.9 |
| 承認 | `concession_mode`（factual / arguendo） | **0.9（最重要）** |
| 残存範囲 | `residual_scope` の有無 | 0.9 |
| 新規性 | rule_state（ADMISSIBLE系／INADMISSIBLE系） | 0.8 |

### A.2 総括固有の割れやすい点

| 割れ方 | 判断の指針 |
| --- | --- |
| 「比較」か「新Attack」か | **相手に新たな反論の必要を生じさせるか**で判断する（§6.2）。ただしこの問いだけで機械判定せず、役割と規則を併せて見る |
| G型が複数当てはまる | 複数可。実際の総括は3つ程度の併用が普通である |
| 軸が複数ある | 主軸を1つ決め、副軸を別に記録する。全部を並列にしない |
| 話者が軸を言っていない | **`comparison_source = judge` として記録する。** 注釈者が話者の代わりに軸を補ってはいけない |
| G10/G14に当たるか | 論点**間**の関係を主張しているときだけ。単に2つの論点を比べているだけならG03〜G09である |
| ディフェンスへの再々反論 | ⑨⑩で出たらX07、⑪⑫で出たら細かい証拠比較（§6.1） |

### A.3 `concession_mode` の付与を特に慎重に行う

**判定結果が変わる唯一の項目である。** 「認めます」と言っただけの発言が、事実承認なのか仮定承認なのかは、前後の文脈でしか決まらない。

判定の手順：

1. その発言の**直前**に、同じ論点への主位的な否定があるか。あれば `arguendo` の可能性が高い
2. Even if / 仮に / たとえ〜としても、に相当する語があるか。あれば `arguendo`
3. どちらも無く、単に「その点は認めます」なら `factual`
4. 判断が分かれたら **`unspecified` として残す**。どちらかへ寄せない

4番目が重要である。この項目は無理に埋めるより、埋まっていないことが見えている方がよい。

### A.4 やらないこと

- 総括で話者が言わなかった軸を、注釈者が補って記録しない
- G10/G14 を「判定に効いた」として記録しない（説明専用）
- 一致率を上げるために、G型の定義を後付けで広げない
