## v02から何を変えたか（参照用）

v01は攻撃と防御を1冊にまとめていた。v02では**攻撃（本書）と防御（v03-防御）に分冊**する。80と18で性質が違い、参照のされ方も違うためである。

**観点1：アプリへ組み入れる**
本書の80パターンを `attack_pattern_master` の正本にする。最大の変更は、**80のうち28は「11のcanonical攻撃種別の子」にならない**ことを明示した点である。W系（比較）・T系の一部・R系の一部は、`clash_events` ではなく別のサブシステムへ行く。これを木構造として実装すると、比較や手続の指摘がノードのダメージ計算に混入する。

そこで各パターンに **`binding`（写像先サブシステム）** を付与した。

**観点2：教材としての有効性**
難易度・頻出度・混同しやすいIDの対・学習順序を付けた。80個を順に覚える教材にはしない。

**内容面の主な追加・変更**

| # | 追加・変更 | 理由 |
| --- | --- | --- |
| 1 | 全80に **`binding`** を付与（§2） | W・T・R系の誤混入を機械的に止める |
| 2 | **I01〜I08に `impact_dimension` を付与**（§9） | v01では8つとも「重要性への攻撃」で一括りだった。計算上まったく同じ扱いになる |
| 3 | **I02の写像規約を明示** | I02（発生可能性が低い）は Value ではなく Probability への攻撃。NOT_IMPORTANT に写像してはいけない |
| 4 | **C08にWARRANTを明示** | 循環論法・内部矛盾はEvidenceの問題ではない。Support Qualityを4値で維持する根拠 |
| 5 | **T系を4分岐に整理**（§11冒頭） | T01/T02/T04＝立論相当、T03＝value_turn、T05/T06＝論点間関係、T07/T08＝手法 |
| 6 | **A03〜A08に `ruleset_conditional`** | HEnDAでのCounterplan許容が未確定。規則版ごとに有効・無効を切り替える |
| 7 | **T07・R05・R08を `technique_meta` へ** | 攻撃種別ではなく「手法」「メタ指摘」。攻撃種別の値にすると分類軸が混ざる |
| 8 | **1発言複数攻撃の分割規約**（§14.2） | R07（選択的未応答）を表現するために必須 |
| 9 | 混同しやすいIDの対（§15.3） | 教材として |

**変えていないこと**：80が唯一の公式分類ではないという位置づけ、各カードの攻撃例と効き方、HEnDAの役割制限、例示が仮想である旨。

## 1. ルールと基本構造（v01から継承）

| 要点 | 本書での扱い |
| --- | --- |
| 立論 | AD・DAは各最大2つ。プランは肯定立論後に変更・追加しない |
| Attack | 相手のAD／DAの証明を攻撃。新たなAD／DAは追加しない。肯定Attackで直前の否定Attackへの防御を先取りしない |
| Defense | 自分のAD／DAを再構築。新プラン・新AD／DA・新たな相手への攻撃は不可 |
| Summary | 攻防後に残った議論を比較。新しい攻撃は不可。既出議論の細かな証拠比較や深い比較の観点は区別する |
| 反転 | Case flip／Link turnが新AD／DAを加えるなら基本的に立論。価値だけのValue turnはAttackでも許容 |
| 代替案 | 現状で既に得られる利益の指摘と、新政策を採択するCounterplanを区別 |

根拠：R1 §§2.1.1〜2.1.8、4.2.1〜4.2.2。

### 1.1 議論の骨格と効き方

現状（政策なし）→政策による変化→中間の因果関係→最終的な利益・弊害。各段階を証拠と理由づけが支える。

| 効き方 | 意味 |
| --- | --- |
| **弱化** | 程度・確率・信頼性を下げる |
| **否定（takeout）** | 不可欠な要素を崩し、その論点の成立を止める |
| **反転（turn）** | 相手の議論を自分側を支持する理由へ変える |
| **比較（weighing）** | 相手の一定の成立を認めても自分側が上回ると示す |

手続上の除外は真偽の否定とは別である。

## 2. binding：攻撃が「どこへ効くか」（v02で新設）

80パターンは同じ種類のものではない。ノードの値を下げるもの、証拠の質を問うもの、規則違反を指摘するもの、比較の仕方を問うものが混在している。**同じ欄に入れると、比較や手続の指摘がノードのダメージとして計算される。**

| binding | 意味 | 該当 | 件数 |
| --- | --- | --- | --- |
| `node_attack` | A・B・Cノードの成立を直接攻撃する | P8・C01〜C07・S8・I8・T03・A01・A02 | 34 |
| `support_quality` | ノードが成立すると評価される理由（Evidence/Warrant/Relevance/Burden）を攻撃する | E8・M8・C08・R04 | 18 |
| `rule_state` | 規則上の採否を問う。真偽の否定ではない | T01・T02・T04、A04・A05、R01〜R03 | 8 |
| `comparison` | 論点の比較の仕方を攻撃する。ノード値は動かない | W01〜W03・W06〜W08、T08 | 7 |
| `cp_response` | 相手が出した代替案への攻撃。対象がAD／DAでない | A03・A06〜A08 | 4 |
| `issue_relation` | 論点と論点の関係を主張する。**説明用であり、数値モデルは参照しない** | W05・T05・T06 | 3 |
| `technique_meta` | 攻撃の手法や、攻撃自体への指摘。内容により再分類される | T07・R05・R08 | 3 |
| `aggregation` | 合計の取り方を攻撃する | W04 | 1 |
| `drop` | 未応答の指摘 | R07 | 1 |
| `defense_quality` | 防御の質への指摘 | R06 | 1 |

> **アプリ上の不変条件**：`binding ≠ node_attack` かつ `binding ≠ support_quality` のパターンIDを持つ `clash_events` は、`r = claimed_effect × support` の計算経路に入らない。CIで静的検査する。

> **tier による分離（v03で追加）**　`attack_pattern_master` に `tier ∈ {core, extension}` を持たせる。`core` は74件、`extension` は A03〜A08 の6件。**`henda-r20` では extension の実データ投入を行わない。** 規則版ごとに有効・無効を切り替えるための `ruleset_conditional` は残すが、既定は無効である。教材でも本体（§4〜§13）には core だけを置き、extension は付録Bへ分離した。

> **`issue_relation` の扱い**：T05・T06・W05は、判定理由の記述には欠かせないが、`clash_leverage` の反実仮想（「Issue i だけを立論終了時へ戻し、他は最終値のまま」）が前提とする論点の独立性を壊す。したがって `issue_relations` テーブルに**説明専用**で記録し、`official_decision_support` の計算はこれを参照しない。

## 3. カードの読み方

```
攻撃例　　　仮想例
防御　　　　v03-防御のID
効き方・注意　判定上の意味と境界
メタ　　　　binding｜canonical（写像先の値）｜難易度｜頻出度
```

難易度：★＝初級／★★＝中級／★★★＝上級。頻出度：高・中・低。
canonicalの値は次の11種（Support Qualityは4値を維持する）。

`NOT_NECESSARY` / `NOT_UNIQUE` / `NO_EFFECT` / `ALTERNATIVE_SOLVES` / `NOT_SOLVENT` / `NOT_IMPORTANT` / `VALUE_TURN` / `EVIDENCE` / `WARRANT` / `RELEVANCE` / `BURDEN`

## 4. E｜証拠の出所・引用への攻撃

すべて `binding = support_quality`。**証拠の弱さはノードの値を直接下げるのではなく、そのノードの Probability をなぜその水準と評価するかの理由になる。** 同じ弱点をEvidenceとProbabilityで二重に減点しない。

### E01　出典不明・原文未確認
**攻撃例**　「調査による」とだけ述べ、機関・年・原文が分からない。
**防御**　D03（証拠の復元）
**効き方・注意**　信頼性の問題。直ちに虚偽・捏造と決めない。
**メタ**　support_quality｜EVIDENCE｜★｜高

### E02　専門性の不一致
**攻撃例**　教育効果を、専門外の著名人の感想だけで証明している。
**防御**　D03
**効き方・注意**　知名度ではなく、その主張を判断できる根拠が対象。
**メタ**　support_quality｜EVIDENCE｜★｜中

### E03　利害関係・資金源
**攻撃例**　販売企業の宣伝だけで、その商品の学習効果を立証している。
**防御**　D03・D04
**効き方・注意**　利害関係は検証理由になるが、それだけで誤りは確定しない。
**メタ**　support_quality｜EVIDENCE｜★★｜中

### E04　情報の古さ・前提変化
**攻撃例**　旧制度下の結果を、制度変更後の予測にそのまま使っている。
**防御**　D03・D04
**効き方・注意**　古いという年数だけでなく、関連する条件変化が必要。
**メタ**　support_quality｜RELEVANCE｜★★｜中

### E05　文脈の切取り
**攻撃例**　原文の「特定の条件で」を落とし、一般的効果として引用している。
**防御**　D03・D07
**効き方・注意**　限定の復元と、故意の歪曲という不正認定は分ける。
**メタ**　support_quality｜EVIDENCE｜★｜高

### E06　翻訳・要約の誇張
**攻撃例**　may improve を「必ず改善する」と訳している。
**防御**　D03・D07
**効き方・注意**　可能性・因果・主語・数量の変化を具体的に指摘する。
**メタ**　support_quality｜EVIDENCE｜★★｜中

### E07　二次引用・伝聞の劣化
**攻撃例**　新聞が紹介した調査を、調査本文の結論と同じだと扱っている。
**防御**　D03
**効き方・注意**　二次資料だから無価値ではない。情報がどこで変わったかが争点。
**メタ**　support_quality｜EVIDENCE｜★★｜中

### E08　証拠が結論を述べていない
**攻撃例**　「利用者が増えた」という証拠で「学力が上がる」と結論づける。
**防御**　D05・D10
**効き方・注意**　証拠自体が正しくても、主張を支えるとは限らない。**証拠と結論の間の理由づけ（Warrant）を問う攻撃**であり、証拠そのものの質を問うE01〜E07とは狙いが違う。
**メタ**　support_quality｜**WARRANT**｜★｜高
**混同注意**　C01（そもそも因果がない）と紙一重。**証拠は正しいがそこから結論が出ない**ならE08、**因果の機序自体がない**ならC01。

## 5. M｜調査方法・統計への攻撃

すべて `binding = support_quality`。E系が「その資料は信用できるか」を問うのに対し、M系は「その資料は何を示しているか」を問う。

### M01　標本数・推定の不確かさ
**攻撃例**　少人数の結果から全国的な効果を断言している。
**防御**　D03・D07
**効き方・注意**　人数だけでなく、必要な精度と主張の強さを比べる。
**メタ**　support_quality｜EVIDENCE｜★｜高

### M02　選択バイアス・代表性
**攻撃例**　意欲の高い希望者だけの成功を、全員に一般化している。
**防御**　D06・D07
**効き方・注意**　参加者特性による効果と政策効果を分ける。
**メタ**　support_quality｜RELEVANCE｜★｜高

### M03　比較群なし・前後比較のみ
**攻撃例**　実施後に改善したが、実施しない場合の変化が示されていない。
**防御**　D03・D05
**効き方・注意**　時系列の一致だけでは政策の追加効果を確定できない。
**メタ**　support_quality｜EVIDENCE｜★★｜高

### M04　測定指標・代理指標の不一致
**攻撃例**　満足度を、実際に身についた能力と同一視している。
**防御**　D03・D07
**効き方・注意**　測ったものと証明したいものの差を攻撃する。
**メタ**　support_quality｜RELEVANCE｜★★｜高
**混同注意**　I07と対。**測定の妥当性**ならM04、**結果の社会的な意味**ならI07。

### M05　分母・単位・基準値の操作
**攻撃例**　割合の増加を人数の増加と混同し、相対変化だけを大きく見せる。
**防御**　D03
**効き方・注意**　数値が正しくても見せ方で影響を過大評価しうる。
**メタ**　support_quality｜EVIDENCE｜★★｜中

### M06　都合のよい事例・期間の選択
**攻撃例**　成功校だけ、または好調な年度だけを抜き出している。
**防御**　D03・D04
**効き方・注意**　不利な結果の存在だけでなく、除外が結論をどう変えるかを示す。
**メタ**　support_quality｜EVIDENCE｜★★｜中

### M07　独自推計・計算の飛躍
**攻撃例**　原典にない仮定を重ねた予測値を、公的統計そのものとして述べる。
**防御**　D03
**効き方・注意**　R1 §3.2.1.1を確認。**計算の誤りとルール不適合は別に記録する。**
**メタ**　support_quality｜EVIDENCE｜★★★｜低
**二重束縛**　`support_quality` と同時に `rule_flags.own_calculation` を立てる。前者は証明の質、後者は手続の問題。

### M08　相反する研究・再現性
**攻撃例**　同じ条件で逆の結果が出ており、単一研究だけでは安定した結論にならない。
**防御**　D04
**効き方・注意**　研究の本数投票にせず、適用性と方法の質を比較する。
**メタ**　support_quality｜EVIDENCE｜★★★｜低

## 6. P｜現状・必要性・非固有性への攻撃

すべて `binding = node_attack`、対象は**Aノード（Observation）**。

### P01　問題の不存在・過大描写
**攻撃例**　困っていると述べた対象では、その問題の存在が示されていない。
**防御**　D02・D03
**効き方・注意**　現状の問題を否定。解決性の否定（S系）とは別。
**メタ**　node_attack / A｜NOT_NECESSARY｜★｜高

### P02　自然改善・既定の変化
**攻撃例**　新政策がなくても、既定の制度変更で改善が進む。
**防御**　D09
**効き方・注意**　政策なしの将来との比較。現在の静止画だけで比べない。
**メタ**　node_attack / A｜NOT_UNIQUE｜★★｜中

### P03　現行制度で既に解決
**攻撃例**　既存の支援で同じ対象に同じ利益が届いている。
**防御**　D09・D13
**効き方・注意**　別手段の存在だけでは不十分。同じ利益が実際に得られるかが必要。
**メタ**　node_attack / A｜NOT_UNIQUE｜★｜高
**混同注意**　A01と対。**現状で既に実行されている**ならP03、**新しく採択する案**ならA01。

### P04　未活用の既存手段
**攻撃例**　利用可能な仕組みを使えば、提案の大半の利益が得られる。
**防御**　D09・D13
**効き方・注意**　実際に進む現状改善か、架空の代替政策かを分ける。
**メタ**　node_attack / A｜NOT_UNIQUE｜★★｜中

### P05　DAの非固有性／Non-unique
**攻撃例**　政策なしでも、同じ弊害が既に起きる／起きる見込みである。
**防御**　D09
**効き方・注意**　既に起きるだけではDAはゼロにならない。**増分が残るかが核心。**
**メタ**　node_attack / A｜NOT_UNIQUE｜★｜高

### P06　ベースラインの取り違え
**攻撃例**　何もしない世界だけを比較相手にし、通常の社会変化を無視する。
**防御**　D09
**効き方・注意**　都合のよい現状仮定を修正する。
**メタ**　node_attack / A｜NOT_NECESSARY｜★★★｜低

### P07　原因・対象の不一致
**攻撃例**　問題は交通事情なのに、教材だけを変えれば解決すると述べる。
**防御**　D02・D05
**効き方・注意**　現状診断と政策の接続が争点。
**メタ**　node_attack / A｜NOT_NECESSARY｜★★｜中
**併用**　C・S系と併用できる。Aノードへの攻撃として記録し、Bノードにも及ぶ場合は別イベントに分割する（§14.2）。

### P08　追加利益・追加被害がない
**攻撃例**　既存施策と対象・効果が重なり、政策による差が示されていない。
**防御**　D09・D14
**効き方・注意**　必要なのは政策の増分。「独創的」「唯一」であること自体ではない。
**メタ**　node_attack / A｜NOT_UNIQUE｜★★｜中

## 7. C｜因果関係・論理への攻撃

C01〜C07は `binding = node_attack`、対象は**Bノード（Link）**。攻撃時は**何段目のリンクか**を必ず指定する（`link_order`）。C08だけは例外。

### C01　最初のリンクがない／No link
**攻撃例**　端末を配るだけでは、学習する行動に結びつく理由がない。
**防御**　D05
**効き方・注意**　政策→最初の変化が切れれば、その経路の利益は成立しにくい。
**メタ**　node_attack / B(link_order=1)｜NO_EFFECT｜★｜高

### C02　中間リンクの断絶
**攻撃例**　練習量が増えても、質が伴わなければ能力向上につながらない。
**防御**　D05
**効き方・注意**　A→B→Cのどこが切れているかを指定する。
**メタ**　node_attack / B(link_order=n)｜NO_EFFECT｜★｜高

### C03　相関と因果の混同
**攻撃例**　端末保有者の成績が高いことから、端末が原因だと断定する。
**防御**　D05・D03
**効き方・注意**　相関の存在を否定せず、因果を証明する不足を指摘する。
**メタ**　node_attack / B｜NO_EFFECT｜★★｜中

### C04　逆因果
**攻撃例**　端末で意欲が上がったのでなく、意欲が高い人が端末を購入したのではないか。
**防御**　D05

## 9. I｜影響の大きさ・価値への攻撃

すべて `binding = node_attack`、対象は**Cノード（Impact）**。

> **v02での最重要変更**　v01ではI01〜I08が8つとも「重要性への攻撃」として同じ扱いだった。しかし8つは**それぞれ別の次元**を狙っている。同じ `NOT_IMPORTANT` として記録すると、「対象が少ない」と「回復可能だ」が計算上まったく同一に扱われる。
>
> そこで各パターンに **`impact_dimension`** を付与した。この次元は、立論資料（v03-立論 §5）でADが主張した主次元と突き合わせる。**主張していない次元を攻撃していれば、それはR05（対象違い）の候補になる。**

### I01　対象人数・範囲が小さい
**攻撃例**　全員の利益としているが、実際の対象は一部に限られる。
**防御**　D07
**効き方・注意**　少人数というだけで価値ゼロにはならない。
**メタ**　node_attack / C｜NOT_IMPORTANT｜dim=**scale**｜★｜高

### I02　発生可能性が低い
**攻撃例**　被害に至る条件が揃う見込みが薄い。
**防御**　D02・D03
**効き方・注意**　可能性ゼロと低確率を区別する。
**メタ**　node_attack / **B（最終リンク）**｜**NO_EFFECT**｜dim=occurrence_likelihood｜★★｜高

> **I02の写像規約（v02で新設・重要）**
> I02は「Impactの価値が小さい」ではなく「**Impactがそもそも起きにくい**」という主張である。これはValueではなくProbabilityへの攻撃であり、`NOT_IMPORTANT` に写像すると確率の問題を価値の問題として記録することになる。
>
> ai-debate-analyzer のモデルは `P = chain_rule(A, B1..Bn)` / `V = C.magnitude` なので、Cノードに確率の欄はない。したがって**I02は「Cへ至る最終リンク（Bn）への `NO_EFFECT`」として写像する**。`impact_dimension = occurrence_likelihood` は説明用に併記する。
>
> AIは素直に `NOT_IMPORTANT` を選ぶ傾向があるので、この規約はプロンプトと写像表の両方に明記する。

### I03　一件当たりの影響が小さい
**攻撃例**　不便を、重大な生活被害と同程度に扱っている。
**防御**　D07
**効き方・注意**　感情的な大きい／小さいではなく具体的変化を示す。
**メタ**　node_attack / C｜NOT_IMPORTANT｜dim=**severity**｜★｜高

### I04　短期間・一時的
**攻撃例**　最初の数日だけの効果を、恒久的な改善としている。
**防御**　D07
**効き方・注意**　期間だけを変え、人数や価値と混同しない。
**メタ**　node_attack / C｜NOT_IMPORTANT｜dim=**timeframe**｜★｜中
**混同注意**　S07と対。**効果が出る時期・持続の仕組み**ならS07（Bノード）、**期間の短さが価値を下げる**ならI04（Cノード）。

### I05　可逆性・回復可能性
**攻撃例**　生じた負担は短期間で回復でき、不可逆な損失ではない。
**防御**　D07
**効き方・注意**　回復可能でも被害ゼロとは限らない。
**メタ**　node_attack / C｜NOT_IMPORTANT｜dim=**reversibility**｜★★｜中

### I06　受益者と被害者の偏り
**攻撃例**　平均利益はあっても、最も困る層には利益が届いていない。
**防御**　D07・D08
**効き方・注意**　平均値だけで公平性を代弁しない。**独立の新被害は立論で扱う。**
**メタ**　node_attack / C｜NOT_IMPORTANT｜dim=**equity**｜★★｜中

### I07　指標と価値の不一致
**攻撃例**　点数上昇が、論題で重視する理解力の改善を意味していない。
**防御**　D03・D05
**効き方・注意**　M04は測定の妥当性、ここでは結果の社会的な意味を主に問う。
**メタ**　node_attack / C｜NOT_IMPORTANT｜dim=**value_relevance**｜★★★｜中

### I08　閾値・飽和・限界効果
**攻撃例**　既に十分な支援があり、追加分による改善はごくわずかである。
**防御**　D08・D09
**効き方・注意**　全体の大きさでなく、追加一単位の価値が争点。
**メタ**　node_attack / C｜NOT_IMPORTANT｜dim=**marginal_utility**｜★★★｜低
**混同注意**　P08と対。**追加利益がそもそも無い**ならP08（Aノード・非固有性）、**追加分はあるが価値が小さい**ならI08（Cノード）。

## 10. W｜比較・重みづけへの攻撃

> **v02での重要な整理**　W系は**ノードへの攻撃ではない**。相手の論点が成立していることを認めたうえで、比較の仕方を問う。したがって `clash_events` のノードダメージ計算（`r = claimed_effect × support`）には入らない。総括（v03-総括 §5）の比較軸と対応する。
>
> `binding = comparison`（W01〜W03・W06〜W08）、`issue_relation`（W05）、`aggregation`（W04）。

### W01　同一基準で劣る／Outweigh
**攻撃例**　両側とも学習機会を重視するが、こちらの方が多くの未参加者に届く。
**防御**　D15
**効き方・注意**　相手の論点を消すのではなく、残存価値で上回る。
**メタ**　comparison｜軸は文脈依存｜★｜高

### W02　期間・単位の不公平な比較
**攻撃例**　一方の年間利益と、他方の一回限りの負担をそのまま比べる。
**防御**　D15
**効き方・注意**　比較の土台を修正する。
**メタ**　comparison｜軸=timeframe｜★★｜中

### W03　大きな数字だけの比較
**攻撃例**　最大人数だけで比較し、実際の到達率や実現可能性を無視している。
**防御**　D15
**効き方・注意**　規模・確率・期間を点検するが、**機械的な乗算を公式採点にしない。**
**メタ**　comparison｜軸=scale＋probability｜★★｜中

### W04　二重計上
**攻撃例**　同じ生徒の同じ改善を、二つの利点として足し合わせている。
**防御**　D14
**効き方・注意**　重複分を調整。二つの議論があるだけでは二重計上ではない。
**メタ**　**aggregation**｜★★★｜低

> **W04のアプリ上の意味（v02で新設）**　`aff_sum = Σ Strength(AD)` という加算モデルそのものへの攻撃である。重複があると合計が主張どおりに立たない。`issue_snapshots.overlap_with_issue_id` / `overlap_ratio` に記録し、AIは候補フラグまで、独立性の確定は人が行う。立論段階の予防は v03-立論 §1.1。

### W05　前提となる価値の優先
**攻撃例**　安全が失われると学習機会も使えないため、安全確保が先である。
**防御**　D15
**効き方・注意**　「命だから勝ち」等の標語でなく、前提関係を証明する。
**メタ**　**issue_relation**｜軸=prerequisite｜★★★｜低

### W06　実現時期・不可逆性の優先
**攻撃例**　遠い将来の小改善より、今生じる回復不能な損失を重視すべきだ。
**防御**　D15
**効き方・注意**　今の被害が常に優先するとは限らない。
**メタ**　comparison｜軸=timeframe＋reversibility｜★★｜中

### W07　公平性・権利と総量の比較
**攻撃例**　多数の小さな利益で、少数者の重大な不利益を埋め合わせてよいのか。
**防御**　D15
**効き方・注意**　人数以外の比較軸。新たな独立被害の後出しに注意。
**メタ**　comparison｜軸=equity｜★★★｜中

### W08　仮に認めても勝つ／Even if
**攻撃例**　相手の効果を認めても、こちらの立論で示した損失が上回る。
**防御**　D16
**効き方・注意**　予備的な比較。**事実としての全面承認と明確に区別する。**
**メタ**　comparison｜`concession_mode = arguendo`｜★★｜高

> **W08のアプリ上の意味（v02で新設）**　「仮に認めても」は事実の承認ではない。これを `concede` として記録すると、ノード値を実際より下げて確定してしまう。`clash_events.concession_mode ∈ {factual, arguendo}` で区別する。**Phase A必須の列。**

## 11. T｜反転・相手の議論の利用

> **v02での整理**　T01〜T08は同じ種類ではない。**4つの別サブシステムへ分岐する。**
>
> | 分岐 | 該当 | 写像先 |
> | --- | --- | --- |
> | 新AD／DA相当（立論で提示すべき） | T01・T02・T04 | Rule State Engine。立論に出れば v03-立論 L16 |
> | 価値だけの反転（Attackで許容） | T03 | `VALUE_TURN`（既存） |
> | 論点間の関係 | T05・T06 | `issue_relations`（説明専用） |
> | 手法・メタ指摘 | T07・T08 | `technique_meta` / `comparison` |

適用注意：新AD／DAに相当するかを内容と提出時点で判別する。［R1、R4〜R6］

### T01　因果の反転／Link turn
**攻撃例**　相手は政策が参加を減らすと言うが、同じ仕組みが参加を増やす。
**防御**　D12
**効き方・注意**　新AD／DAになる反転はHEnDAでは基本的に立論で提示。
**メタ**　rule_state｜候補状態 `INADMISSIBLE_NEW_ADVANTAGE` / `NEW_DA`｜★★★｜低
**規則の根拠（v03で追加）**　R1 §2.1.4 側注は、相手のDisadvantageを裏返して「事態はむしろ好転する」と付け加える形の議論（Link turn）は基本的に立論の仕事だとしている。

### T02　中間リンクの反転
**攻撃例**　利用増加は負担を増すのでなく、経験の蓄積で負担を減らす。
**防御**　D12
**効き方・注意**　因果の一段階を反転。新利益の追加なら立論上の制約。
**メタ**　rule_state｜★★★｜低

### T03　価値の反転／Value・Impact turn
**攻撃例**　相手は依存の減少を損失とするが、自立という点では望ましい結果である。
**防御**　D12
**効き方・注意**　価値だけの反転はR1のAttackで許容。新しい因果の害を足すこととは別。
**メタ**　node_attack / C｜**VALUE_TURN**｜★★★｜中
**規則の根拠（v03で追加）**　R1 §2.1.3・§2.1.4 の側注は、相手の重要性だけを攻撃して「良いことがもたらされるとはいえず、むしろ避けるべき価値だ」（または「悪いことがもたらされるとはいえず、むしろ歓迎すべき価値だ」）と**価値だけを転倒するアタックは許される**と明記している。T03の許容はここに直接の根拠がある。

> **T03のアプリ上の扱い**　Impactの**大きさと向き**を分けて記録する（`impact_direction ∈ {+1, -1}`）。HEnDA Judge Sheetに存在しない符号付きスコアを公式表示へ持ち込まない。turnの採否で勝者候補が変わる場合は `winner_suggestion = REVIEW_REQUIRED` で止める（`value_turn_mode = review_gate`）。

### T04　ケースの反転／Case flip
**攻撃例**　問題を解消するはずの政策が、同じ問題をむしろ悪化させる。
**防御**　D12
**効き方・注意**　単なる無効化より強い主張。独立DAとしての立論提示が基本。
**メタ**　rule_state｜★★★｜低
**規則の根拠（v03で追加）**　R1 §2.1.3 側注は、相手のAdvantageを裏返して「事態はむしろ悪化する」と付け加える形の議論（Case flip）は基本的に否定側の立論の仕事だとしている。
**同一実体**　立論で提示された場合は v03-立論 **L16**。二重登録しない。

### T05　DAがADを壊す／DA turns case
**攻撃例**　既出の人員流出DAが起きると、既出の学習支援ADも実現しない。
**防御**　D12
**効き方・注意**　結びつきも適時に提示。総括で新たな破壊経路を作らない。
**メタ**　**issue_relation**｜★★★｜中

### T06　ADがDAを軽減する
**攻撃例**　既出の効率化ADが、既出の人手不足DAを緩和する。
**防御**　D13
**効き方・注意**　既出のつながりを比較に使う。都合のよい補完策を後から追加しない。
**メタ**　**issue_relation**｜★★★｜低

### T07　相手の証拠・承認の利用
**攻撃例**　相手の原文にある「既存支援でも改善する」を、必要性への反論に用いる。
**防御**　D11
**効き方・注意**　証拠利用は**手法の名称**。内容により非固有性・否定・反転に再分類する。
**メタ**　**technique_meta**｜★★｜中
**記録**　T07単独では `attack_type` にならない。実体（例：P03）を `attack_pattern_id` に、T07を `technique_tags[]` に記録する。

### T08　相手の基準を適用する反論
**攻撃例**　相手が公平性を最優先するなら、同じ基準で相手の主張も評価すべきだ。
**防御**　D11・D15
**効き方・注意**　内在的な反論。矛盾指摘や比較であり、必ずしも厳密なturnではない。
**メタ**　comparison｜★★★｜低

### 11.1 Double turnの注意（v01から継承・v02で検出規約を追加）

同じ論点で「政策はXを減らす」（Link turn）と「Xは良い」（Value turn）を無条件に同時主張すると、「政策は良いものを減らす」と自分に不利になる。因果と価値の反転を混ぜず、別集団・別条件なら違いを明示する。純粋な反転が残る場合、元の論点を黙って捨てても反転は消えない。［R4・R5］

> **アプリでの検出**　同一 `target_argument_id` に対し、同一側から `T01/T02`（link turn）と `T03`（value turn）の両方が `ADMISSIBLE` で存在し、`concession_mode = factual` である場合、`rule_flags.double_turn` を候補として立てる。**自動除外はしない**。判定への影響は人が決める。

## 12. A｜代替手段・Counterplanと応答

> **適用注意（v01から継承・v02で強化）**　A03〜A08はCounterplanを扱う一般形式の知識を含む。**HEnDAでの自由な新政策追加を意味しない。** 本書ではこれらに `ruleset_conditional = true` を付け、規則版ごとに有効・無効を切り替えられるようにする。`henda-r20` での既定は「記録は可能・判定材料としては要確認」。［R1、R7］

### A01　他の方法でも同じ利益
**攻撃例**　既存の対面支援で同程度の利益が得られるため、政策固有の利益は小さい。
**防御**　D13
**効き方・注意**　現状で実現する手段なら必要性攻撃。新規政策ならCounterplanの検討へ。
**メタ**　node_attack / B｜**ALTERNATIVE_SOLVES**｜★★｜高
**混同注意**　P03と対。**現状で既に実行されている**ならP03（Aノード・非固有性）、**新たに採択する案**ならA01。

### A02　より低負担の手段
**攻撃例**　別の手段なら、同じ効果をより少ない負担で実現できる。
**防御**　D13・D15
**効き方・注意**　単に望ましい案を思いつくだけでは、比較対象として成立しない。
**メタ**　node_attack / B｜ALTERNATIVE_SOLVES｜★★★｜中

### A03〜A08　Counterplan形式（Extension・本体から分離）

**v03でこの6件を付録Bへ移した。** A03〜A08はCounterplanを扱う一般形式の知識であり、HEnDAの正規機能ではない。R1 §2.1.5・§2.1.6 はディフェンスでの新プラン追加を明示的に禁じており、代替案を「採択する世界」へ比較対象を置き換える運用は原規則から導けない。

したがって：

- `tier = extension`、`ruleset_conditional = true`
- **`henda-r20` では実データ投入を行わない**
- 教材の本体には置かず、指導者・研究用として付録Bに分離する
- HEnDA経験者のレビューゲートを通るまで、この扱いを変えない

内容は**付録B**を参照。A01・A02（他の方法でも同じ利益／より低負担の手段）は Core のままである。これらは相手のADの**非固有性・解決性への攻撃**であって、新政策の採択提案ではないためである。

## 14. 記録と分割の規約（v02で新設）

### 14.1 記録項目

| 記録項目 | 例 | アプリの列 |
| --- | --- | --- |
| 対象 | AD1のBリンク2「教材提供→継続利用」 | `target_node_id`（+ `target_event_id` / `target_type`） |
| 攻撃ID | S02 | `attack_pattern_id` + `attack_pattern_ver` |
| 写像先 | node_attack / NOT_SOLVENT | `binding` / `attack_type`（masterから導出） |
| Impact次元 | I系のみ | `impact_dimension` |
| 手法タグ | T07・R05・R08 | `technique_tags[]` |
| 主張・根拠 | 発言引用、音声時刻、出典・該当箇所 | `rationale` + `segment_ids`（必須） |
| 効果の主張 | None / Minor / Moderate / Major / Decisive | `claimed_effect_cat` |
| 裏づけ | Unsupported / Weak / Adequate / Strong | `support_cat` |
| 承認の種別 | 事実として／仮定として | `concession_mode` |
| 規則適合 | 新プランの追加か、既出条件の再説明か | `rule_state` |
| 状態 | 未応答／応答あり／部分解消／解消／**判断保留** | `recovery_cat` + `review_status` |
| 残存結論 | 家庭利用への効果は弱化。校内利用は別途検討 | `residual_scope` |
| 比較への接続 | 対象限定後の利益を既出の費用DAと比較 | `comparison_events` |

### 14.2 1発言に複数の攻撃があるときは分割する

**規約**：`clash_events` は「1つの攻撃対象 × 1つの攻撃ID」で1件とする。1回の発言に3つの攻撃が含まれるなら、`segment_id` が同じ3件を作る。

**なぜ必須か**：R07（選択的応答）は「3つのうち2つに答え、1つを残した」という事象である。発言単位で1件にまとめると、`recovery_cat` が1つしか付かず、部分未応答が表現できない。同じ理由で、v01が述べる「同じ攻撃を複数分類しただけで二重に減点しない」も、分割の単位が明確でないと守れない。

**二重減点の防止**：分割した3件が同じノードを攻撃している場合、`r` は個別に掛け合わせず、**最も強い1件を採る**か、`chain_rule` と同じ扱いで統合する（`scoring_config.multi_attack_rule`、校正対象）。ここを決めないと、攻撃を細かく言い換えるだけでダメージが増える。

### 14.3 人が確認すべき境界（v01から継承）

「証拠が弱い」と「虚偽」、「低確率」と「ゼロ」、「部分解決」と「無効」、「別案の存在」と「元の案の敗北」、「未応答」と「正しい」、「比較」と「新Attack」を分ける。AIは不明点を人間の確認に回し、原発言にない理由を補って成立させない。

学習表示で数値やHPを用いる場合も、何が削られ／守られたのかを理由とともに示す。分類ラベルだけから固定点を減算したり、学習用数値の合計を公式勝敗へ直結させたりしない。内容の評価と話し方・伝達の評価も区別する。［R1 §4.2、R3］

## 15. 教材としての使い方（v02で新設）

### 15.1 Core Attack 15（初級版・v03で新設）

**80個を生徒に見せない。** 80分類は指導者とAI内部のためのものである。教室では次の15個から始める。証拠・現状・因果・解決性・重要性の5領域を、それぞれ3個ずつ押さえる構成にした。

| 領域 | ID | 一言でいうと |
| --- | --- | --- |
| **証拠** | E01 | どこの資料か分からない |
| | E05 | 条件を落として引用している |
| | E08 | その証拠はその結論を述べていない |
| **現状** | P01 | その問題が実在するか示されていない |
| | P03 | 今の制度で既に同じ利益が出ている |
| | P05 | 政策がなくても同じ弊害が起きる |
| **因果** | C01 | 政策から最初の変化への理由がない |
| | C02 | 途中の一段がつながっていない |
| | M02 | 特別な人たちの結果を全員に広げている |
| **解決性** | S01 | 根本の原因に手が届いていない |
| | S02 | 効果に不可欠な条件がプランにない |
| | S04 | 制度があっても実際には使われない |
| **重要性** | I01 | 対象が思っているより少ない |
| | I03 | 一人あたりの影響が小さい |
| | I04 | 効果が続かない |

この15個で、実際の試合で出る攻撃のかなりの部分をカバーできる。**まずこの15個を「どのノードを狙ったか」まで言えるようにする。**

加えて、判定に直結する手続の2つ（**R03** 新しい議論、**R07** 未応答）は早い段階で教える。これはAttackの技術というより、試合の見方である。

### 15.2 学習順序

| 段階 | 攻撃ID | 数 | 目標 |
| --- | --- | --- | --- |
| **第1段階** | Core Attack 15（§15.1）＋R03・R07 | 17 | 5領域から1つずつ出せる。狙ったノードを言える |
| **第2段階** | E02〜E04・E06・E07・M01・M03〜M06・P02・P04・P07・P08・C03・C05・C07・S03・S05・S07・I02・I05・I06・W01・W02・R04 | 26 | 効き方（弱化／否定）を言い分けられる |
| **第3段階** | 残り31（core） | 31 | 反転・比較・手続を、規則上の制約を踏まえて使える |
| **参考** | 付録B（extension 6） | 6 | 指導者・研究用。HEnDAでは使わない |

**T系は初心者に勧めない。** T01/T02/T04は新DA相当としてRule State違反になりやすい。**A03〜A08は教室で扱わない**（付録Bへ分離）。

### 15.3 混同しやすいIDの対

指導で最も時間を使うべき部分である。

| 対 | 見分け方 |
| --- | --- |
| **E08 ⇔ C01** | 証拠は正しいがそこから結論が出ない＝E08。因果の機序自体がない＝C01 |
| **M04 ⇔ I07** | 測定の妥当性＝M04。結果の社会的な意味＝I07 |
| **P03 ⇔ A01** | 現状で既に実行されている＝P03。新たに採択する案＝A01 |
| **P05 ⇔ I02** | 政策なしでも同じ被害が起きる＝P05（非固有性）。被害の条件が揃わない＝I02（発生可能性） |
| **P08 ⇔ I08** | 追加利益がそもそも無い＝P08。追加分はあるが価値が小さい＝I08 |
| **S07 ⇔ I04** | 効果が出る時期・持続の仕組み＝S07（Bノード）。期間の短さが価値を下げる＝I04（Cノード） |
| **S08 ⇔ T04** | 改善分がゼロへ相殺＝S08。むしろ悪化する＝T04（反転・新DA相当） |
| **C05 ⇔ M03** | 別原因がある＝C05（因果）。比較群がない＝M03（方法） |
| **T03 ⇔ T01/T04** | 同じ結果の**評価**を逆にする＝T03（Attackで可）。**因果の向き**を逆にする＝T01/T04（立論で提示） |
| **R05 ⇔ R08** | 攻撃側が相手の主張を読み替えた＝R05。防御側が話をずらした＝R08 |

### 15.4 練習課題

1. 同じ立論に対して「証拠（E/M）」「現状（P）」「因果（C/S）」「価値（I）」の四方向から各一つ攻撃する。
2. それぞれについて、**攻撃対象がAノードかBノードかCノードか**を指定する。Bなら何段目か。
3. Iで攻撃した場合、8つの次元のどれを狙ったかを述べる。相手の立論がその次元を主張していなければ、それはR05になり得ることを確認する。
4. 反転を用いた場合は、因果と価値のどちらを反転したか説明し、HEnDAでAttackとして許されるかを判定する。
5. 最後に「認める部分」と「残る利益」を一文ずつ述べる。

## 付録A. 注釈ガイドライン（実試合へのID付与と一致率検証）

分類をこれ以上増やす段階は終わっている。次にやるべきは、**実際のHEnDA試合3〜10本にL／A／D／GのIDを人手で付け、二つのことを確かめること**である。

1. **全発言を分類できるか**（被覆率）
2. **複数人が同じIDを付けるか**（一致率）

ここを通らないうちにAIの抽出精度を測っても、測っている対象が定まらない。

### A.1 付与の単位

| 対象 | 単位 | 付けるID |
| --- | --- | --- |
| 立論 | 論点（AD1/AD2/DA1/DA2）ごと | L01〜L16（複数可） |
| 立論 | Cノードごと | `impact_dimension_primary`（8値） |
| Attack | 1攻撃対象 × 1攻撃ID | 本書の80（§14.2の分割規約に従う） |
| Defense | 親Attackごと | D01〜D18、`recovery_cat`、`concession_mode` |
| Summary | 比較ごと | G01〜G16、`comparison_axis`（8値） |
| 全段階 | 疑わしい発言 | X01〜X07、rule_state |

### A.2 付与の手順

1. 転写と時刻を確定させる（IDより先）
2. 立論のノード分解を2人で行い、突き合わせる。**ここが合わないと以降がすべて合わない**
3. Attack を分割規約に従って切り出す。切り出しの境界を先に合意する
4. 各Attackにcore 74からIDを付ける。付けられないものは「未分類」として残す（無理に近いIDへ寄せない）
5. Defenseを親Attackに紐づけ、`recovery_cat` と `residual_scope` を書く
6. Summaryの比較に軸を付ける

### A.3 測る指標

| 指標 | 目標 | 意味 |
| --- | --- | --- |
| **被覆率** | 判定に関わる発言の90%以上 | 「未分類」が多いなら分類体系に穴がある |
| **family一致率** | 0.8以上 | E/M/P/C/S/I/W/T/Rのどれか、で一致するか |
| **ID一致率** | 0.6以上 | 80のどれか、まで一致するか。ここは低くて当然 |
| **binding一致率** | 0.9以上 | **これが最重要。** node_attackかsupport_qualityかcomparisonかで割れると、計算結果が変わる |
| **target_node一致率** | 0.8以上 | A/B/Cのどれを狙ったか。Bなら何段目か |
| **impact_dimension一致率** | 0.7以上 | I系を付けたとき、8次元のどれか |

**ID一致率よりbinding一致率を優先する。** E03とE05で割れても計算結果は変わらないが、W04をnode_attackに入れるかaggregationに入れるかで変わる。

### A.4 一致しなかったときにすること

分類体系を直す前に、**なぜ割れたか**を3種類に分ける。

| 割れ方 | 対応 |
| --- | --- |
| 発言が実際に両方の性質を持つ | 分割規約（§14.2）で2件にする。体系は直さない |
| ID定義の記述が曖昧 | 本書のカードの「効き方・注意」を書き直す |
| 体系にその攻撃の場所がない | **新IDを足す前に、既存IDのbindingで受けられないか確認する。** 受けられるなら記述の問題である |

3つ目に該当するものだけを、次版で追加する候補にする。

### A.5 やらないこと

- **AIの出力を正解として付与しない。** 人が独立に付けたものと比較する
- **一致率を上げるために定義を後付けで緩めない**
- **Extension（付録B）を付与対象にしない。** HEnDAの試合には出ないはずのもので、出たならrule_stateの問題として記録する
- 一致率が低いIDを、それだけの理由で削除しない。低い理由が「難しいから」なのか「定義が悪いから」なのかを分ける

## 付録B. Extension｜Counterplan形式の6パターン（`tier = extension`）

> **この付録の位置づけ**　以下はCounterplanを扱う一般形式（主に米国Policy Debate）の知識であり、**HEnDAの正規機能ではない**。指導者・研究用の参考として残すが、`henda-r20` では実データ投入を行わず、教材の本体にも置かない。使用の可否は、その大会の規則・論題定義・特別規定に照合したうえで、HEnDA経験者の確認を経て判断する。［R1、R7］

### A03　政策の一部だけで足りる
**攻撃例**　必要な部分だけ実施すれば、利益を維持し不要な負担を避けられる。
**防御**　D13・D14
**効き方・注意**　一般形式の部分採用型CP等。HEnDAにそのまま移植せず許容を確認。
**メタ**　cp_response｜`ruleset_conditional`｜★★★｜低

### A04　手段・実施主体の変更
**攻撃例**　同じ目的でも、規制ではなく支援／別の主体の実施が良いと提案する。
**防御**　D13
**効き方・注意**　新政策の提案。論題の比較世界を勝手に変更しない。
**メタ**　rule_state｜`ruleset_conditional`｜★★★｜低

### A05　時期・条件・試行の変更
**攻撃例**　直ちに全面実施せず、試行や条件付き実施なら負担を避けられる。
**防御**　D13・D15
**効き方・注意**　一般形式の遅延・条件付きCP。HEnDAでの採用を保証しない。
**メタ**　rule_state｜`ruleset_conditional`｜★★★｜低

### A06　代替案の解決性不足
**攻撃例**　代替案では対象の一部に届かず、元の政策の利益を代替できない。
**防御**　—（代替案を出した側が答える）
**効き方・注意**　これは**代替案に対する攻撃**。元の政策が完全解決する証明とは別。
**メタ**　**cp_response**｜`ruleset_conditional`｜★★★｜低
**注記**　`target_node_id` がAD／DAのノードを指さない。代替案は `argument_nodes` に登録されていないため、`target_type = counterplan` が必要になる。Phase Aでは列のみ確保し、実データ投入はしない。

### A07　併用できる／Permutation
**攻撃例**　二つの手段は併用でき、代替案を選ぶために元の政策を捨てる必要がない。
**防御**　D14
**効き方・注意**　一般形式では競合性のテスト。HEnDAのDefenseで新プランを宣言しない。
**メタ**　cp_response｜`ruleset_conditional`｜★★★｜低

### A08　代替案の純利益がない
**攻撃例**　代替案固有の負担があり、元の政策との差引きで優位ではない。
**防御**　D15
**効き方・注意**　一般形式のNet benefit比較。新DAの提示時期・本数に注意。
**メタ**　cp_response｜`ruleset_conditional`｜★★★｜低

### Extension を Core から分離する理由

1. **原規則に採択の枠組みがない。** R1が定めるのは、肯定側のプランを採るか採らないかの比較である。第三の政策を採択する世界を持ち込む手続が規定されていない。
2. **役割制限と衝突する。** A04・A05は新政策の提案であり、Attackの役割（相手のAD／DAの証明を攻撃する）を超える。A07（Permutation）はDefense段階でのプラン宣言に近づく。
3. **対象が `argument_nodes` にない。** A06は相手が出した代替案を攻撃するもので、AD／DAのノードを指さない。`target_type = counterplan` が要るが、その代替案自体が登録されていない。
4. **混ぜると Core が汚れる。** A01（他の方法でも同じ利益）は現状で実現する手段の指摘であり Core だが、A04（別の主体がやるべきだ）は新政策である。同じ「代替案」の語で括ると、この線が消える。

### アプリ上の扱い

| 項目 | 設定 |
| --- | --- |
| `tier` | `extension` |
| `ruleset_conditional` | `true` |
| `henda-r20` での既定 | 無効（実データ投入なし） |
| `target_type` | A06のみ `counterplan`（Phase Aでは列のみ確保） |
| CI検査 | `tier = extension` のイベントが `ruleset_version = henda-r20` の試合に存在したら失敗させる |
