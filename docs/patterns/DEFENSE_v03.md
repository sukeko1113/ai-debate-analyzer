## v02から何を変えたか（参照用）

v01では防御18パターンが攻撃80と同じ冊子に入っていた。v02では**独立した冊子**にする。防御は攻撃と1対1ではなく、攻撃IDから引く逆引きが必要であり、参照のされ方が違うためである。

**観点1：アプリへ組み入れる**
D01〜D18を `defense_pattern_master` の正本にし、各パターンに **`recovery_cat` へのヒント写像**を付ける。あわせて、v01のモデルでは表現できなかった3つを列として要求する。

| 表現できなかったもの | 該当 | 追加する列 |
| --- | --- | --- |
| 事実として認めたのか、仮定として認めたのか | D07・D15・D16 | `concession_mode ∈ {factual, arguendo}` |
| 攻撃は成立するがノード値には影響しない | D10 | `recovery_cat` に `Immaterial` を追加 |
| 何がどの範囲で残ったのか | D07・D08・D09・D17 | `residual_scope` |

**観点2：教材としての有効性**
攻撃IDから防御IDを引く**逆引き表**（§5）を新設した。試合中に必要なのはこの方向である。また、v01では本文に散っていた「やってはいけない防御」を **X01〜X06** として独立させた。禁じ手を明示的に教える方が、正しい防御を18個並べるより効果が高い。

**内容面の主な追加・変更**

| # | 追加・変更 | 理由 |
| --- | --- | --- |
| 1 | 全18に `recovery_cat` ヒント写像を付与 | AIの候補提示とジャッジの整理を揃える |
| 2 | **`concession_mode`（事実／仮定）を明示**（§3.3） | 仮定承認を事実承認として記録するとノード値を実際より下げて確定する |
| 3 | **`recovery_cat` に `Immaterial` を追加**（D10） | 「回復した」のではなく「そもそも影響しなかった」を表現する |
| 4 | **`residual_scope` を必須化**（D07〜D09・D17） | 総括の残存価値比較（G11・G16）が成り立たない |
| 5 | **禁じ手 X01〜X06 を新設**（§4） | R02・R03・R06・R08と対になる。教材価値が高い |
| 6 | 攻撃ID→防御ID の逆引き表（§5） | 試合中に必要な方向 |
| 7 | 難易度・頻出度・学習順序を付与 | 教材として |

**変えていないこと**：18パターンの内容と対応関係、HEnDAの役割制限、防御の中心は自分のAD／DAの再構築であるという位置づけ。

## 1. 防御の役割とHEnDAの境界

| 項目 | 判断と実践 |
| --- | --- |
| Defense | 自分のAD／DAを再構築する。3分 |
| してよいこと | 攻撃への直接応答、既存プランの範囲での説明の具体化、限定承認、既出根拠の再構築、**今までの議論の比較をする観点**（下記1.1） |
| してはいけないこと | 新プラン、新AD／DA相当、相手への新しい攻撃 |
| 否定Defense | 直前の肯定Defenseへの再々反論はしない |
| 総括との違い | Defenseは自分の論点の再構築が役割、総括は全体の比較が役割 |

根拠：R1 §§2.1.5〜2.1.6。

### 1.1 Defense中の比較は許容され、むしろ推奨されている（v03で新設）

v02では比較をすべて総括の仕事として扱い、D15・D16を `summary_links` へ送っていた。これは原規則の読み違いだった。

R1 §2.1.5・§2.1.6 は、肯定・否定いずれのディフェンスについても、**相手側に直接アタックを付け加えるのでないならば、今までの議論の比較をする観点を出すことは許される**としている。側注はさらに踏み込み、相手の重要性そのものを攻撃するのではなく自陣の重要性が上回ると述べることは、守ることに主眼を置いた間接的な攻めであり、総括につながるので推奨されるとしている。

したがって比較は**総括だけのものではない**。

| 段階 | 比較の可否 | 条件 |
| --- | --- | --- |
| 立論 | 可（限定的） | 政策なしとの比較。相手のAD／DAはまだ出ていない |
| Attack | 不可（比較は役割外） | 攻撃が役割 |
| **Defense** | **可・推奨** | **相手側に直接アタックを付け加えないこと** |
| 総括 | 可（中心的役割） | 新Attack・新AD／DAを足さないこと |

> **アプリ連携（v03で変更）**　比較の記録先を `summary_links` から **`comparison_events`（ステージ横断型テーブル）** へ変更する。Defense段階の比較が記録できないと、総括で「Defenseで既に比較していた」ことを示せず、G12（Even if）の適時性を検証できない。
>
> `comparison_events` は `stage_no` を持ち、`adds_direct_attack`（相手側に直接アタックを付け加えているか）のフラグを持つ。Defense段階でこのフラグが真になった場合、`INADMISSIBLE_NEW_ATTACK` の候補になる。

### 1.2 防御の四つの動作

すべての防御は次の4つの組み合わせでできている。

| 動作 | 内容 | 該当D |
| --- | --- | --- |
| **正す** | 攻撃が対象を取り違えている／読み替えていることを示す | D01・D06・D18 |
| **答える** | 攻撃が依存する事実・推論を直接崩す | D02・D03・D04・D05・D11・D12・D13 |
| **狭める** | 成立する範囲を限定して残す | D07・D08・D09・D17 |
| **比べる** | 攻撃の成立を認めたうえで、比較で上回る | D14・D15・D16 |

**順序が重要**：正す→答える→狭める→比べる。逆順にすると、まだ答えられる攻撃に対して先に譲歩することになる。初心者が最もよく失敗するのがここである。

### 1.3 「どこまで残ったか」を言わない防御は防御にならない

攻撃への応答を述べただけで終える発言が非常に多い。ジャッジが記録するのは応答の有無ではなく、**その結果どこまで残ったか**である。

すべての防御は次の一文で終える。

> したがって、元の立論のうち［対象］における［効果］は残ります。

この一文が `residual_scope` になる。

## 2. 防御の記録形式

```
内容　　　　何をする防御か
使う場面　　どの攻撃に対して
対応攻撃ID　v03-攻撃のID
メタ　　　　recovery_catヒント｜追加属性｜難易度｜頻出度
```

**`recovery_cat`（回復の程度）** — Attackの内部ダメージ `r` を `r' = r × (1-g)` で再計算するときの `g`。

| 値 | 意味 | 初期値 |
| --- | --- | --- |
| `None` | 答えていない／論点をずらしただけ | 0 |
| `Minor` | 部分的に触れたが核心に答えていない | .25 |
| `Partial` | 核心の一部に答えた | .50 |
| `Substantial` | 核心に答え、大部分が回復した | .75 |
| `Full` | 攻撃が解消された | 1.0 |
| **`Immaterial`** | **攻撃は成立するが、このノードの値には影響しない**（v02で追加） | 別扱い |

`Immaterial` は `Full` と数値上は近いが意味が違う。`Full` は「攻撃を解消した」、`Immaterial` は「攻撃は正しいが、結論は別の根拠で立っている」である。判定理由の文面が変わるので、区別して記録する。

## 3. 防御パターン D01〜D18

### D01　正確化
**内容**　相手が攻撃した命題と、実際の自分の発言を照合する。誤読なら範囲を戻す。
**使う場面**　相手が主張を強く読み替えて攻撃してきたとき。
**対応攻撃ID**　R05・R08・C08
**メタ**　recovery=Full〜Substantial｜★｜高

> 成立すれば攻撃そのものが対象違いになるので、ノード値は下がらない。アプリでは相手の `clash_events` に対する `target_mismatch` 候補として記録する。

### D02　前提の否定
**内容**　攻撃が依存する事実や条件が成立しないと示す。例：利用支援は既に存在する。
**使う場面**　攻撃が「〜が無い」「〜ができない」と述べているとき。
**対応攻撃ID**　P01・P07・S01〜S05・C06・I02
**メタ**　recovery=Full〜Substantial｜★★｜高

### D03　証拠の復元
**内容**　原文・方法・対象を示し、疑義が結論を崩さない範囲を説明する。
**使う場面**　E系・M系の攻撃全般。
**対応攻撃ID**　E01〜E07・M01・M03・M05〜M08
**メタ**　recovery=Substantial〜Partial｜★｜高

> 原文を試合中に提示できない場合、成立範囲を狭めるのが正しい（D07へ）。「後で出せます」は防御にならない。ASRや記録欠損で確認できない場合は、アプリでは `evidence_status = unverifiable` へ送り、証明の弱さとして自動的に減点しない。

### D04　証拠の比較
**内容**　双方の資料の対象・時期・方法を比べ、今回の条件に近い方を説明する。
**使う場面**　相手が別の資料を出して矛盾を指摘したとき。
**対応攻撃ID**　E03・E04・M06・M08
**メタ**　recovery=Substantial｜★★｜中

### D05　推論の修復
**内容**　欠けたと指摘された因果の接続を、**既存プランの範囲で**説明する。
**使う場面**　C系の攻撃全般。
**対応攻撃ID**　C01〜C07・E08・M03・P07・R04・R06
**メタ**　recovery=Substantial〜Partial｜★★｜高

> **境界**　「既存プランの範囲で」が肝。ここで新しい施策を持ち出すとX02（後出しのプラン変更）になる。

### D06　適用条件の区別
**内容**　相手の反例は別の年齢・制度・時期だと示し、なぜ差が重要か説明する。
**使う場面**　相手が「他ではこうだった」と示したとき。
**対応攻撃ID**　M02・M06・S06・E04
**メタ**　recovery=Substantial〜Partial｜★★｜中

### D07　限定承認
**内容**　過大な部分は認め、確実に維持できる人数・期間・程度へ主張を狭める。
**使う場面**　I系・M系の攻撃で、主張が広すぎたとき。
**対応攻撃ID**　I01・I03〜I06・M01・M02・M04・E05・E06・C07
**メタ**　recovery=Partial｜**`residual_scope` 必須**｜`concession_mode=factual`｜★★｜高

> **必ず残す範囲を言う。** 「一部は認めます」で終えると、ジャッジはどこが残ったか記録できず、総括で比較できない。
> 例：「全生徒の学力向上は証明できていません。**端末不足が障壁となる生徒の参加機会**については残ります。」

### D08　部分解決の擁護
**内容**　全解決は不要で、有意な改善が残ると示す。その改善をDAと比較する。
**使う場面**　S01（根本原因に作用しない）系。
**対応攻撃ID**　S01・S08・I06・I08
**メタ**　recovery=Partial｜`residual_scope` 必須｜★★｜高

### D09　増分の提示
**内容**　現状でも発生することを認め、政策が増減させる分だけを示す。
**使う場面**　非固有性（P系）の攻撃。
**対応攻撃ID**　P02〜P06・P08・I08
**メタ**　recovery=Substantial〜Partial｜`residual_scope` 必須｜★★｜高

> P系への正しい防御はほぼこれ一択である。「既にある」と言われたら、増える分を示す以外にない。

### D10　独立根拠の維持
**内容**　攻撃された証拠が弱まっても、既にある別の根拠・経路が結論を支えると示す。新ADの追加はしない。
**使う場面**　証拠1本を崩されたとき。
**対応攻撃ID**　E01〜E08・C05・C08・M08
**メタ**　**recovery=`Immaterial`**｜★★★｜中

> **v02での変更**　v01のモデルでは `p' = p × (1-r)` が単調減少なので、「攻撃は成立するがノード値は下がらない」を表現できなかった。`Immaterial` はこのためにある。
>
> 成立条件は厳しい。**攻撃された根拠を除いても、立論の時点で提示済みの別根拠だけで同じ結論が立つこと。** 試合中に新しい根拠を出すのはX03になる。

### D11　共通前提の確認
**内容**　相手も認めた条件から、どこまで結論が導けるか再構築する。承認の範囲を広げない。
**使う場面**　相手が質疑や攻撃の中で何かを認めたとき。
**対応攻撃ID**　T07・T08・R08
**メタ**　recovery=Substantial｜★★★｜低

> 質疑での相手の承認は、後続スピーチで明示的に引用しない限り判定材料にならない（`qa_effect_mode = cited_only`）。D11を使うときは、いつどのスピーチで相手が何と言ったかを明示する。

### D12　反転の解除
**内容**　反転された因果または価値を特定し、その方向・強さ・適用条件を論証し直す。
**使う場面**　T系の攻撃。
**対応攻撃ID**　T01〜T05
**メタ**　recovery=Substantial〜Partial｜★★★｜中

> **四つの応答経路**（v01深掘り①から）：①反転の根拠を崩す ②対象の違いを示す ③元の因果・価値を再構築する ④反転が成立しても既出の別論点で上回る（→D15へ）。
> **新規の再反転をDefenseへ追加することは役割制限に照合する。**

### D13　代替案の実効性検査
**内容**　他の方法が同じ対象へ実際に届くか、元の政策なしで実行されるかを問う。
**使う場面**　A系・P03・P04。
**対応攻撃ID**　A01〜A06・P03・P04・T06
**メタ**　recovery=Substantial｜★★｜中

> **六つの確認質問**（v01深掘り②から）：現状か新政策か／同じ対象に届くか／同じ効果が出るか／併用できるか／元の政策に増分があるか／ルール上使えるか。

### D14　併用・追加利益の提示
**内容**　二者択一でないことと、元の政策に追加価値が残ることを示す。**新プランを宣言しない。**
**使う場面**　A07（Permutation）、W04（二重計上）。
**対応攻撃ID**　A03・A07・P08・W04
**メタ**　recovery=Partial｜★★★｜低

### D15　比較による防御
**内容**　一定の攻撃を認めても、残る利益が相手の損失を上回ると比較する。
**使う場面**　W系の攻撃、または狭めた後の締め。
**対応攻撃ID**　W01〜W03・W06〜W08・T08・A08
**メタ**　recovery=Partial｜`concession_mode` を明示｜★★｜高

> D15は**ノード値を回復させる防御ではない**。比較の主張であり、総括（G系）へ引き継ぐものである。アプリでは `comparison_events`（ステージ横断）側で扱い、`recovery_cat` の数値には反映しない。
>
> **v03での位置づけ変更**　R1 §2.1.5・§2.1.6 により、Defense中の比較は許容され推奨されている（§1.1）。D15はDefense段階の正規の動作であって、総括の前借りではない。ただし「相手側に直接アタックを付け加えない」条件を満たす必要があり、満たさなければ `INADMISSIBLE_NEW_ATTACK` になる。

### D16　条件付きの二段構え
**内容**　まず主位的に攻撃を否定し、次に「仮に認めても」と独立した比較を述べる。
**使う場面**　攻撃が成立するか微妙で、成立しても勝てるとき。
**対応攻撃ID**　W08、および任意の攻撃
**メタ**　主位＝各Dのrecovery／予備＝比較｜**`concession_mode=arguendo` 必須**｜★★★｜中

> **v02での最重要注記**　D16の二段目は**事実の承認ではない**。「仮に認めても」を `concede` として記録すると、実際には否定している攻撃について、ノード値を下げて確定してしまう。これは画面上きれいに埋まって見えるので、誰も気づかない種類の誤りである。
>
> `concession_mode = arguendo` で記録し、`r` の計算には主位の応答（一段目）だけを使う。二段目は比較の材料として `comparison_events` へ送る。
>
> **発話上の要件**：Even if / 仮に認めても、を明示的に言うこと。言わずに比較へ移ると、ジャッジは事実承認と区別できない。

### D17　限定的撤回・争点整理
**内容**　維持できない部分は明示して撤回し、残る既出論点へ集中する。**成立した相手の反転は放置しない。**
**使う場面**　時間が足りず、すべてに答えられないとき。
**対応攻撃ID**　R07、および任意の攻撃
**メタ**　撤回部分 recovery=None／残す部分は別イベント｜`residual_scope` 必須｜★★★｜中

> **撤回は分割を伴う。** 「AD1のうちBリンク3は撤回し、Bリンク1・2で立てる」のように、何を捨てて何を残すかをノード単位で言う。論点まるごとを黙って落とすのはX05になる。
>
> **反転が残っている論点は捨てても消えない。** T系の攻撃が成立している場合、その論点を撤回しても反転による不利益は残る（R5）。撤回する前にD12で解除する必要がある。

### D18　役割・新規性の整理
**内容**　元の発言箇所を示し、正当な補強・比較か、禁止された新規論点かを区別する。
**使う場面**　相手からR01〜R03を指摘されたとき、または相手のR03を指摘するとき。
**対応攻撃ID**　R01〜R03
**メタ**　rule_state へ｜recovery非適用｜★★★｜中

> D18はノードの防御ではなく手続の主張である。`rule_state` の判定材料になるが、`r` の計算には入らない。

## 4. 禁じ手 X01〜X07（v02で新設・v03で拡張）

v01では本文中に注意として散っていたものを独立させる。**これらは防御に見えるが防御ではない。** 相手からR系の攻撃を受け、Rule Stateで判定材料から外れる。

| ID | 禁じ手 | 何が起きるか | 対応する攻撃 | rule_state |
| --- | --- | --- | --- | --- |
| **X01** | 論点ずらし | 因果を問われて深刻さを語る。攻撃は解消していない | R06 | `recovery_cat = None〜Minor` |
| **X02** | 後出しのプラン変更 | 欠落を新しい施策で埋める。判定材料から外れる | R02 | `INADMISSIBLE_NEW_PLAN` |
| **X03** | **新しい議論を成立させる証拠の追加** | 既出AD／DAの再構築を超え、新しい因果・利益・攻撃を成立させるEvidence。判定材料から外れる | R03 | `INADMISSIBLE_NEW_*` |
| **X04** | 再読・繰り返し | 同じ証拠をもう一度読む。応答したことにならない | R06 | `recovery_cat = None` |
| **X05** | 沈黙による撤回 | 答えられない論点に触れずに済ませる。反転は消えない | R07 | `DROPPED` |
| **X06** | 仮定を事実として述べる | 「仮に認めても」を言わずに比較へ移る | — | `concession_mode` の誤記録 |
| **X07** | 直前ディフェンスへの再々反論 | 否定ディフェンスで、直前の肯定ディフェンスに反論する | — | `INADMISSIBLE_PREMATURE_REBUTTAL` |

> **X03の範囲（v03で限定）**　v02では「Defenseで初めて出す証拠」をすべてX03としていたが、これは原規則より厳しい。
>
> R1 §2.1.5・§2.1.6 がディフェンスについて禁じているのは、**新プラン・新AD／DA相当・相手への新しいアタック**である。「初出の証拠」そのものを一律に禁じる文言はない。むしろ「相手からなんのアタックもこなかったAD／DAについて説明し直し、強調することは当然許される」とあり、再構築のための説明の具体化は許容されている。
>
> したがってX03は次に限定する。
>
> - **X03に該当する**：その証拠がなければ立たない新しい因果経路・新しい利益／被害・相手への新しい攻撃を、Defenseで初めて成立させる場合
> - **X03に該当しない**：既出の主張の説明を具体化する証拠、既出の因果を裏づけ直す証拠、比較の観点を支える証拠（§1.1）
>
> 判定は「初出かどうか」ではなく「**相手に新たな反論の必要を生じさせるか**」で行う。境界的な場合はAIが断定せず、`REVIEW_REQUIRED` として人へ返す。

> **X07の根拠**　R1 §2.1.6 は否定ディフェンスについて、直前の肯定ディフェンスへの再々反論を明示的に禁じている。ただし総括では、肯定ディフェンスへの再々反論にあたる点を**細かい証拠比較として出すことが許される**（§2.1.8）。したがってX07はディフェンス段階に限った禁じ手であり、同じ内容が総括で出た場合はX07にしない。

**X06が最も見つけにくい。** 他の6つはジャッジが気づくが、X06は本人も気づかずにやる。「相手の言うとおりだとしても」と一言入れるだけで防げる。

**教材としての使い方**：正しい防御18個を教える前に、この6つを教える。初心者の防御の失敗はほぼこの6つのどれかである。

## 7. 教材としての使い方（v02で新設）

### 7.1 学習順序

| 段階 | 扱う内容 | 数 | 目標 |
| --- | --- | --- | --- |
| **第0段階** | 禁じ手 X01〜X07 | 7 | やってはいけないことを知る。特にX01（論点ずらし）とX04（再読） |
| **第1段階** | D01・D02・D03・D05・D07・D09 | 6 | 正す・答える・狭めるの基本形。試合の8割はこの6つで足りる |
| **第2段階** | D04・D06・D08・D13・D15 | 5 | 比較・適用条件・代替案への応答 |
| **第3段階** | D10・D11・D12・D14・D16・D17・D18 | 7 | 反転の解除、二段構え、撤回、手続 |

**D16（二段構え）は第3段階に置く。** 早く教えると、主位の応答をせずにいきなり「仮に認めても」から始める癖がつく。まず答えられるようになってから教える。

### 7.2 防御が最も失敗する三点

1. **順序を間違える**　狭める・比べるを先にやってしまう。まだ答えられる攻撃に譲歩している。§1.2の順序で確認する。
2. **残った範囲を言わない**　応答して終わる。§1.3の一文を必ず言う。
3. **仮定と事実を混ぜる**　X06。「仮に認めても」を明示する。

### 7.3 練習課題

1. 一つのADに対する4つの攻撃（E・P・C・I各1つ）を受け取り、逆引き表（§5）から第1選択の防御を選ぶ。
2. それぞれについて、§1.3の一文（「したがって〜は残ります」）を書く。
3. 4つのうち1つは意図的に答えず、D17（限定的撤回）として明示的に捨てる。X05（沈黙による撤回）との違いを説明する。
4. 最も弱い1つについてD16（二段構え）を作り、主位と予備を明確に分けて発話する。
5. 自分の防御をX01〜X07で自己点検する。

### 7.4 指導者・AIへの渡し方

「防御が弱い」ではなく、「AD1のBリンク2に対するS02への応答が、D02なのかD07なのか定まっていない」と指定する。防御IDと `residual_scope` の有無で指摘すると、生徒が何を直すべきかが具体的になる。

## 9. アプリ側の実装メモ

| 供給先 | 内容 | フェーズ |
| --- | --- | --- |
| `defense_pattern_master` | D01〜D18（18行） | Phase A |
| `defense_antipattern_master` | X01〜X07（7行） | Phase A |
| `clash_events.defense_pattern_id` / `pattern_ver` | NULL可 | Phase A（列） |
| **`comparison_events`（ステージ横断）** | `stage_no`, `adds_direct_attack`, 比較軸, 根拠 | **Phase A必須** |
| **`clash_events.concession_mode`** | `{factual, arguendo}` | **Phase A必須** |
| **`clash_events.residual_scope`** | テキスト＋segment_ids | **Phase A必須** |
| **`recovery_cat` に `Immaterial` 追加** | enum変更 | **Phase A必須** |
| `rule_flags` に X01〜X07 | 候補フラグ（自動除外しない） | Phase B |
| 逆引き表 | 学習UI・防御候補の提示 | Phase B |

**Phase A必須の4つを後から足せない理由**：`concession_mode` が無いままデータが入ると、事実承認と仮定承認が区別できないまま `r` が計算され、確定したバロットに影響する。後から列を足しても、過去のイベントがどちらだったかは音声に戻らないと分からない。`residual_scope` も同様で、総括の比較が成立しない記録が蓄積する。`Immaterial` はenum変更なので、データ投入後の追加はマイグレーションを伴う。`comparison_events` は、Defense段階の比較を `summary_links` に押し込んだデータが溜まると、後からステージを分離できない。

**判定式に入れないもの**：防御ID・難易度・頻出度はラベルである。`g`（回復の程度）は `recovery_cat` だけから決まり、どの防御パターンを使ったかでは変わらない。「高度な防御だから回復が大きい」という扱いをしない。

## 付録A. 注釈ガイドライン（防御部分）

実試合3〜10本へのID付与で、防御について確認すること。詳細な手順と指標は v03-攻撃 付録A を正本とする。

### A.1 付与するもの

| 対象 | 付けるID | 一致率の目標 |
| --- | --- | --- |
| 親Attackへの紐づけ | `parent_event_id` | **0.85（最重要）** |
| 防御ごと | D01〜D18（複数可） | 0.6 |
| 防御ごと | `recovery_cat`（6値） | 0.7 |
| 承認 | `concession_mode` | **0.9（最重要）** |
| 残存範囲 | `residual_scope` の有無 | 0.9 |
| 疑わしい発言 | X01〜X07 | 0.7 |

### A.2 紐づけを最優先する理由

防御は単独では意味を持たない。**どの攻撃への応答か**が決まって初めて `recovery_cat` が意味を持つ。1つの発言が3つの攻撃に答えているなら、3件に分割して3つの `parent_event_id` を持たせる（攻撃資料 §14.2の分割規約）。

紐づけが割れる典型は、**話者がどの攻撃に答えているか言わない**場合である。その場合は「紐づけ不明」として残し、注釈者が推測で結びつけない。紐づけ不明の件数そのものが、指導上有用な指標になる。

### A.3 防御固有の割れやすい点

| 割れ方 | 判断の指針 |
| --- | --- |
| `recovery_cat` の段階 | **核心に答えたか**を基準にする。話の長さや熱量ではない |
| D07（限定承認）かD17（限定的撤回）か | 狭めて**残す**ならD07、明示して**捨てる**ならD17 |
| D10（Immaterial）に当たるか | 攻撃された根拠を除いても、**立論時点で提示済みの**別根拠だけで結論が立つか。試合中に出した新根拠ならX03 |
| X03に当たるか | 初出かどうかではなく、**新しい因果・利益・攻撃を成立させているか**（§4） |
| X05（沈黙による撤回）か記録欠損か | `coverage_status` と `audibility` を先に確認する。ここを取り違えると、起きていないことで選手を不利にする |
| X07に当たるか | ⑨⑩のディフェンス段階に限る。⑪⑫で同じ内容が出たら細かい証拠比較（総括資料 §6.1） |

### A.4 やらないこと

- 紐づけ不明の防御を、近い攻撃へ推測で結びつけない
- `residual_scope` を注釈者が補って書かない。話者が言わなかったなら「無し」と記録する
- X05を、記録欠損・聞き取り不能の区間から導出しない
